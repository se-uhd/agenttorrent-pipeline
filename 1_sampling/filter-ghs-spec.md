# Filter a GHS retrieval into the sampling frame

## Context

`4_filter_ghs.py` turns the retrieval that `../data/sampling/ghs_retrieval.json` names into the sampling frame. It reads GHS's rows and GitHub's responses from the cache of retrievals (`ghs-cache-spec.md`, `query-github-spec.md`), merges them, applies eight filter steps and records what each step removed and what remained. It writes `../data/sampling/ghs_filtered.json` with the sampling frame in `items`. `_metadata` contains the retrieval that the sampling frame came from, the config and the record of the filter steps, which `4_data-analysis/dataset/filter_steps_table.py` renders for the paper. The classification stage reads each repository's name, GitHub id, default branch, HEAD commit, description and activity. From `_metadata`, it reads the retrieval and what the fork heuristic needs: the query's `contributorsMin` and the window. The analysis reads the sampling frame's `mainLanguage`, `createdAt`, `contributors`, `commits` and `size`, and the publication reads its scalar fields.

## Rationale

The sampling frame is meant to contain "actively maintained software projects with a sufficiently
long development history, written in one of the major programming languages", the purpose that
Mohsenimofidi et al. state for the filters that this stage continues (*Context Engineering for AI
Agents in Open-Source Software*, MSR 2026). Each criterion below addresses one way in which a
GitHub repository can fail that purpose. The reasons are quoted from the papers that used these
criteria: that study, Galster et al. (*Configuring Agentic AI Coding Tools: An Exploratory Study*,
AIware 2026) and the dataset paper (*A Dataset of Agentic AI Coding Tool Configurations*,
AIware 2026). Where the risk is one of the perils that Kalliamvakou et al. measured (*The
Promises and Perils of Mining GitHub*, MSR 2014, <https://doi.org/10.1145/2597073.2597074>),
the peril is quoted as well. Every quotation was checked against its source on 2026-10-14.

### The query (`config/ghs_download.yaml`, `download-ghs-spec.md`)

| Criterion | Reason |
|---|---|
| At least 10 stars | GHS collects only such repositories, because its crawler takes repositories "having at least 10 stars", a bound that "aims at drastically reducing the number of repositories we store and makes the data collection more scalable" (Dabić et al., *Sampling Projects in GitHub for MSR Studies*, MSR 2021, <https://arxiv.org/abs/2103.04682>). The bound is GHS's, and this stage does not set it |
| At least two contributors (`contributorsMin`) and at least one pull request (`pullsMin`) | "The contributor and pull request thresholds exclude toy and solo projects" (dataset paper), because "single-contributor projects often represent personal experiments rather than collaborative software" (Galster et al.). The perils: "Peril V: Two thirds of projects [...] are personal.", with the strategy "To avoid personal projects, the number of committers should be considered.", and "Peril VI: Only a fraction of projects use pull requests." |
| No forks (`excludeForks`) | "Excluding forks avoids duplicated codebases" (dataset paper). The peril: "Peril I: A repository is not necessarily a project." The cleanup step checks GitHub's own flag again, because GHS's flag can be months old |
| A license (`hasLicense`) | "The presence of a license signals the author's intent that the project be reused" (Galster et al.), and "requiring a license enables downstream open-source filtering" (dataset paper). The license step applies that filtering |
| Created at least 18 months before the window's end date, and a commit in the 6 months before it | "The age and recency requirements filter both immature and stale repositories" (dataset paper). The peril: "Peril III: Most projects are inactive.", with the strategy "To identify active projects, consider the number of recent commits and pull requests." |

### The filter steps

| Step | Reason |
|---|---|
| 1. Gone | The later stages read and clone every repository in the sampling frame, and a repository that GitHub no longer serves under its name can be neither read nor cloned. A row that the GitHub query left unresolved has none of the GitHub values that the later steps read, and no response shows whether GitHub has the repository. A repository that GitHub found without its id cannot be labeled, because the later stages key a repository by GitHub's id. GHS applied the window's bound on the creation date to the repository that it crawled under the name. A repository that GitHub created under that name after the bound is therefore another repository, created after the window. Merged with GHS's row, it would enter the sampling frame with the counts of the earlier repository |
| 2. Duplicates | A repository that GHS has under two names is one project. Kept under both names, it would count twice in the activity medians and could be sampled twice |
| 3. Cleanup | Each flag contradicts an actively maintained project or a stable repository. GitHub's schema describes an archived repository as one that "is unmaintained", and its documentation says that archiving makes a repository "read-only for all users" and indicates "that it's no longer actively maintained". A disabled repository is one that GitHub blocks. A locked repository is in a transition that GitHub names: a billing or trade-control restriction, a migration, a move, a rename or an ownership transfer. A fork falls under Peril I, and the step reads GitHub's current fork flag |
| 4. Missing data | The activity step and the analyses read these counts, and a row without them cannot be compared |
| 5. Licenses | The sampling frame contains open-source software. The OSI defines open-source licenses as "licenses that comply with the Open Source Definition", which "allow software to be freely used, modified, and shared" (<https://opensource.org/licenses>). The release also redistributes the configuration artifacts that the pipeline collects from these repositories. The SPDX license list records which licenses the OSI approved, and the step reads the copy in `config/spdx_licenses.json`, version 3.29.0 since 2026-10-15. The five approvals that are new in that version (CDDL 1.1, Python License 2.0.1, the curl License, the CNRI Python Open Source GPL Compatible License Agreement and `BSD - ask to endorse`) change no sampling frame, because GitHub reports a repository under one of them as "Other". Licensee, which identifies a repository's license for GitHub, recognizes 47 licenses (<https://github.com/licensee/licensee/tree/9261af40f46d2039094e8219933914b6e11b3591/vendor/choosealicense.com/_licenses>) and none of the five. Licenses for works other than software, such as Creative Commons licenses for content, the GFDL for documentation and the ODbL for data, are not OSI-approved, and the step removes them. It also removes "Other", a license file that GitHub cannot identify. Four OSI-approved licenses are for other works, and `config/licenses.csv` excludes them: the SIL Open Font License 1.1, with the stated goal "to stimulate worldwide development of collaborative font projects", and the three CERN Open Hardware Licences 2.0, which support "the freedom to use, study, modify, share and distribute hardware designs and products". The OSI test already removes the licenses of the other nine exclusions, because the tracked copy of the SPDX list does not mark them as OSI-approved. These exclusions keep content, document and data licenses out of the sampling frame whatever a refreshed copy of the list contains. The peril behind the step is "Peril IV: A large portion of repositories are not for software development." Mohsenimofidi et al. also left out the licenses that fewer repositories used than the median license. The step applies no such adoption cutoff (`license_min_count_percentile` is 0, as it was for the sampling frame of March 2026), and every OSI-approved software license counts, however few repositories use it |
| 6. Languages | The sampling frame contains projects "written in one of the major programming languages" (Mohsenimofidi et al.), and Galster et al. restricted their sample to the ten most common languages "so that every repository in our sample is most likely a software project". The step counts the ten in each retrieval and follows the population rather than a list fixed in March 2026 |
| 7. Educational | "Peril IV: A large portion of repositories are not for software development." The survey of Kalliamvakou et al. found repositories used "for experimentation, hosting their websites, and for academic/class projects". Tutorials, courses, interview preparation and resource lists such as `awesome-*` collect material rather than develop software. The step removes the repositories that their name or topics identify as such. The classification stage reads the README for the rest, as the peril's strategy says: "Researchers should review the description and README file to ensure the project fits their research needs." Example, sample and demo code collections count as educational by a decision of 2026-10-15, because they demonstrate a product rather than develop one. Patterns that match substrings remove software. `\blearning-` inside `machine-learning-library` matches dlib and stable-baselines3, and `course` matches concourse and discourse. Matched against the owner part of the name, a pattern removes MercuryWorkshop's software. Of the labeled repositories that the earlier substring patterns removed, <!--s:educational_2026_10_15.old_precision_percent-->62%<!--/s--> were educational, against <!--s:educational_2026_10_15.new_precision_percent-->92%<!--/s--> for the current patterns |
| 8. Activity | "Peril II: Most projects have very few commits." Mohsenimofidi et al. excluded repositories "with fewer than 271 commits (median) or fewer than 7 watchers (median)", and Galster et al. adopted the medians, "filtering out low-activity or poorly-followed repositories". The step takes the medians of what remains in each retrieval |

## Key decisions

- **Language:** Python 3.14, in the single script `4_filter_ghs.py`, with the standard library, `requests` for the SPDX list and `pyyaml` for the config. The filter uses no pandas. Its filter steps are list comprehensions over dicts, and it computes the quantile as numpy's default linear interpolation does. Every tie goes by name, so the sampling frame does not depend on a sort implementation
- The sampling frame takes GitHub's value where GitHub returned one, because GHS refreshes a repository only when it crawls a push of that repository and its flags can therefore be months old. GHS also writes every timestamp on a 12-hour clock without AM/PM. `merge` lays GitHub's response over GHS's row: the name, GitHub's repository id as `id`, `createdAt`, `pushedAt` and `updatedAt` in UTC, the archived, disabled, locked, fork, private and mirror flags, the license, the primary language as `mainLanguage`, the stars, the default branch and its HEAD commit as `lastCommitSHA` and `lastCommit`, and the description, which the classification reads. GHS's id and name stay as `ghsId` and `ghsName`, and `githubStatus` holds GitHub's status for the repository. The sampling frame keeps GHS's values for the fields that only GHS has: the commit, contributor, issue, pull request and watcher counts, the topics, the languages and the code metrics
- The filter steps, in order:
  1. **Gone:** The step removes a row when GitHub has no public repository under the name or blocks access to it, or when the GitHub query left the row `unresolved` because GitHub returned no response for it in any round of the query (`query-github-spec.md`). It also removes a row when GitHub found the repository without its id, or when GitHub created the repository under the name after the window's bound on the creation date. The step counts the unresolved rows in `values.unresolved`, apart from the repositories that GitHub does not have, and the repositories found without an id in `values.without_id`. GitHub's GraphQL schema declares a repository's `databaseId` as `Int`, which may be null ([schema](https://docs.github.com/public/fpt/schema.docs.graphql), read on 2026-10-18). A row without an id, if kept, would stop the classification at every start, because the classification reads the id as an integer. The duplicates step would also take rows without an id that were created in the same second for one repository and keep only one of them. No retrieval of October 2026 contains such a row. The step removes the row of a public repository with an id that GitHub created after the window's `created_max` and counts these rows in `values.created_after_window`. The filter reads `created_max` from the retrieval's index row (`window_created_max`). GHS applied `created_max` to its own `createdAt`, which describes the repository that GHS crawled under the name, and none of the other filter steps tests the creation date again. A repository under the name that GitHub created after `created_max` is therefore another repository. The repository that GHS crawled was deleted, renamed or transferred, and the name was taken again. The step compares the day of GitHub's `createdAt` with `created_max`, as `3_compare_retrievals.py` compares days, because GHS writes its times on a 12-hour clock without AM/PM and the hour that GHS compared with its bound cannot be read from its row. A repository that GitHub created on the day of `created_max` stays. Over the retrieval of 2026-10-12, with the `created_max` 2025-04-01, the step removes <!--s:retrieval_2026_10_12.filter.created_after_window-->109<!--/s--> such rows, such as `google/cel-go`, created on GitHub on 2026-09-03, and `alfa-addon/addon`, created on 2026-05-07. An index row without a date as `created_max` makes the filter exit 1, because a blank compared as a day would remove every row
  2. **Duplicates:** rows that GitHub resolves to one repository. GHS adds a row when it crawls a repository under a new name, and it keeps the row under the old name. A renamed or transferred repository can therefore appear twice, and such rows share GitHub's id and creation time. The step keeps the row that GHS has under the current name, else the row with the most commits, else the row with the lowest GHS id. It then leaves out every row of a name under which GitHub returned two repositories, as happens when one repository gave up the name and another took it while the GitHub query gathered the responses of the retrieval. The later stages join by name, and the responses do not show which repository holds the name now. The step counts such names in `values.shared_names` when there is at least one, and the GitHub query of the next retrieval queries them again. Creation time alone does not identify a repository. The GHS search result of March has <!--s:release_2026_03.created_at_groups-->1,959<!--/s--> groups of rows that share a creation time. In <!--s:release_2026_03.created_at_groups_unrelated-->792<!--/s--> of them, the rows differ in repository name and HEAD, such as `apache/karaf` and `apache/maven-surefire`, which a migration created in the same second. The filter that built the sampling frame of 2026-03-17 keyed duplicates on the repository name after the owner and on the creation time. That key misses <!--s:release_2026_03.old_rule_missed_case_groups-->117<!--/s--> groups of the GHS search result of March with repository names that differ only in case. It also misses <!--s:release_2026_03.old_rule_missed_renamed_groups-->18<!--/s--> groups of renamed repositories, with rows that share a HEAD under different repository names
  3. **Cleanup:** archived, disabled, locked and forked repositories, by GitHub's flags
  4. **Missing data:** no pull request or issue count in GHS
  5. **Licenses:** OSI-approved by the SPDX list, minus the licenses that `config/licenses.csv` excludes, minus licenses below `license_min_count_percentile` (<!--s:parameters.1_sampling.config.ghs_filter.license_min_count_percentile-->0<!--/s-->, which excludes none). The step compares names without their double quotes (`license_key`). GitHub's GraphQL API writes `BSD 3-Clause "New" or "Revised" License` as SPDX does, and GHS writes it without the quotes. The two spellings differ for <!--s:retrieval_2026_10_05.license_quotes_only-->9,549<!--/s--> of the repositories that GitHub found in the retrieval of 2026-10-05. Compared with the quotes, the exclusion `BSD 4-Clause Original or Old License`, in GHS's spelling, would miss GitHub's spelling. GitHub omits "only" after the names of the GNU licenses, and `GITHUB_TO_SPDX` maps those names to SPDX's
  6. **Languages:** the `top_n_languages` (<!--s:parameters.1_sampling.config.ghs_filter.top_n_languages-->10<!--/s-->) most common primary languages that the end date of the retrieval covers, with a tie in count going to the name that sorts first. The download reads the languages that this step kept from the sampling frame's `_metadata`, because these languages need a recent crawl date before the download of the GHS search result. For a language that the end date left out, the download reads `filter_languages` and `top_n_languages` from this config, or `--top-languages` from a step argument of the filter. It then applies the license step with this script's code over the rows of the GHS search result to find whether this step would keep the language (`download-ghs-spec.md`). When this step ranks such a language within its number of languages, it passes over the language and keeps the next most common language instead (below)
  7. **Educational:** a topic that matches `educational_topic_regex`, or the repository part of the current name, without the owner, that matches `educational_name_regex` regardless of case. The patterns match whole topics and name segments. Each alternative has a precision of at least 0.8 on the hand labels of the 2026-10-12 retrieval in `../data/sampling/educational/labels.csv` (<!--s:educational_2026_10_15.labels-->2,510<!--/s--> repositories, with `precision.csv`). `TestTheEducationalRules` requires every alternative to remove a labeled educational repository and nine in ten labeled removals to be educational
  8. **Activity:** at least the configured quantile (the median) of commits and watchers of what remains, or an absolute minimum when the config or the command line sets one
- Repositories at one head commit have one history, as a mirror and the repository that it copies have. All of them stay in the sampling frame, and of those that the classification labels as engineered projects, it keeps in the sample, of the repositories that neither GitHub's mark nor the model's response describes as a mirror, the one that GitHub created first (`../2_classification/classify-repos-spec.md`). Until a decision of 2026-10-31, a ninth filter step chose before any label existed and kept the repository created first. In the retrieval of 2026-10-23, that step kept zzzeek/sqlalchemy, zzzeek/alembic and zzzeek/mako, personal copies with the description "THIS IS NOT THE OFFICIAL REPO - PLEASE SUBMIT PRs ETC AT:" and the address of the sqlalchemy repository. Run `2026-10-23T093036Z` labeled these copies `false`. The step left out sqlalchemy/sqlalchemy, sqlalchemy/alembic and sqlalchemy/mako, so SQLAlchemy, Alembic and Mako were in neither the sampling frame nor the sample. The sampling frame of 2026-10-23, which the development dataset uses, was filtered with that step
- The duplicates step comes before the thresholds, because a repository listed twice would otherwise count twice in the medians
- Each license of a sampling frame needs a review. `config/licenses.csv` contains one row per license that the sampling frame keeps (`software`) or that the step excludes by name (`excluded`), each with its SPDX id, the reason quoted from the license, the page and the date on which the page was read. The license step records in `values.licenses` every license that it read, with its repositories, its OSI approval, its decision, the review's decision and five example repositories, which are the same five for the same names. It writes this table to `../data/sampling/ghs_licenses.csv`, with each license's count in the table that it replaces
- A license that the step would keep and that no row covers stays in the sampling frame, so that an unattended run continues. The step names the license in a warning and in `values.unreviewed`. `--check-licenses` reads the table. It exits 2 when the sampling frame keeps a license that is not reviewed as software, when a license reviewed as software is not OSI-approved in the tracked SPDX list, or when the table contains an OSI approval that the tracked list no longer gives. It exits 1 when it cannot read the table, the review or the list. `verify` and CI run the check, so that a new license needs a person's review after each run, as a new path glob does for the heuristics
- A filter step records a key, a description and the values that it decided by, such as the allowed licenses, the kept languages and the activity thresholds. The table of the filter steps reads these values rather than parsing a description
- The SPDX list is part of the code, refreshed and reviewed before each NAS run. `config/spdx_licenses.json` contains the names of the OSI-approved licenses, the list's `license_list_version` and `release_date`, the date on which it was `read` and its `source`. The filter only reads the file. A list fetched at run time into the empty data root of a NAS run would filter the production run with a list that nobody had reviewed. When the list is missing or unreadable, or names no license, the filter exits 1, because the license step would remove every repository
- `--refresh-spdx` fetches the current list, writes it and logs each license that gained or lost its OSI approval. It exits 2 when there is such a license, 0 when the approvals are unchanged, and 1 when it cannot fetch the list or the list names no OSI-approved license. The license step records the list's version and the SHA-256 of `config/licenses.csv` in its values, so that the record of the sampling frame and the release's `sampling.json` name the list and the review that the sampling frame was filtered with. `--dry-run` writes neither the sampling frame nor the table
- The sampling frame keeps GHS's order of the rows that remain, by ascending GHS id
- The filter rejects a GitHub response that lacks a field that the GitHub query requests, so that the sampling frame never has a blank in the field's place. The responses recorded on 2026-10-05, for example, have no description. Merged, they would leave every repository in that sampling frame without one. `2_query_github.py` queries GitHub again for such responses
- The filter rejects a config key that it does not read, such as `filter_redirects` of the earlier filter, instead of ignoring it silently
- The step `languages` ranks only the languages that the end date of the retrieval covers (`step_languages`). A language that the end date left out has a crawl date before the window's end date, or none. GHS then lacks the pushes of that language after its crawl date, and the window does not cover its repositories completely. The filter reads the crawl dates and the end date that the download wrote into the retrieval's index row (`left_out_languages`). The download ends the window on the oldest crawl date of the languages that it does not leave out, and it leaves out only a language with a crawl date older than its lag limit or with no crawl date. A crawl date before the end date therefore marks exactly the languages that the download left out (`download-ghs-spec.md`). A retrieval with a date as its end date has no crawl dates and leaves no language out
- The step goes down its ranking until it has kept `top_n_languages` languages. It passes over each language that the end date left out, and the next most common language that the end date covers takes its place. The step names each language that it passed over in a warning, with its crawl date, and records the languages in `values.left_out`, each with its crawl date or null. The step does not name a language that the end date left out and that ranks after the last language kept, because the step would not keep it in any case. With `filter_languages: false`, the step keeps every language that the end date covers, records the languages that it left out in the same way, and is recorded as skipped when there are none. The table of the filter steps and the README of the release name the languages of `values.left_out` (`4_data-analysis/dataset/filter-steps-table-spec.md`, `docs/steps/release.md`)
- The download checks, as far as the rows of the GHS search result show, whether the filter would keep a language that the end date left out, for the number of languages that the filter kept when the download ran (`check_left_out`). When it finds such a language, the download names it in a warning. It takes the retrieval if the previous sampling frame recorded the languages that it kept, and it fails the retrieval without that list, as on the first Start. The download counts GHS's values over the rows under a license that the filter keeps, while this step counts GitHub's values after the gone, duplicates, cleanup and missing data steps. The two counts can rank a language near the last place differently. A filter that keeps more languages afterwards ranks more languages as well, whether by a larger `--top-languages` with `--from repository_filtering` or by an image that raises `top_n_languages` within a month. In each of these cases the download took the retrieval, and a download run again with the same setting decides the same way. A filter that refused the retrieval with exit 1 would therefore stop the run at every Start until a person intervened. The step leaves such a language out instead, so that the run continues with a sampling frame that the window covers, and the release names the language among its evidence limits
- The filter exits 1 when the crawl dates in the index row are not a JSON object, as it does for any other part of the retrieval that it cannot read, because the step cannot tell which languages the window covers. Only a damaged cache of retrievals causes this failure, and it is the only case in which the crawl dates stop the run

## Script: `4_filter_ghs.py`

### CLI interface

```
python3 4_filter_ghs.py [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--config` | `config/ghs_filter.yaml` | The YAML config |
| `--cache-dir` | `../data/sampling/ghs_retrievals/` | The cache of retrievals |
| `--pointer` | `../data/sampling/ghs_retrieval.json` | The file that names the retrieval |
| `--output` | the config's `output_path` (`../data/sampling/ghs_filtered.json`) | The sampling frame |
| `--dry-run` | off | Run every filter step and write nothing |
| `--top-languages` | the config's `top_n_languages` (<!--s:parameters.1_sampling.config.ghs_filter.top_n_languages-->10<!--/s-->) | Languages kept |
| `--commits-min`, `--watchers-min` | *(none)* | Absolute activity minimums, over the quantile |

### Function structure

**`FilterConfig`**, **`FilterStep`**: the config, with its keys checked, and the record of one filter step

**`merge(ghs, github)`**, **`load_rows(cache_dir, pointer)`**: the merged rows of the retrieval, GitHub's responses checked to be for the same rows in the same order

**`read_spdx_list(path)`**, **`fetch_spdx_list()`**, **`refresh_spdx_list(path)`**, **`is_osi_approved(name, osi)`**, **`load_reviewed_licenses(path)`**, **`license_examples(names)`**, **`license_table(items, osi, reviewed, allowed)`**, **`quantile(values, share)`**, **`allowed_licenses(items, osi, exclusions, percentile)`**: the licenses and the review of each license

**`step_gone`**, **`duplicate_choice`**, **`step_duplicates`**, **`step_cleanup`**, **`step_missing_data`**, **`step_licenses`**, **`left_out_reason`**, **`step_languages`**, **`step_educational`**, **`step_activity`**, **`run_steps`**: the eight filter steps, and why the end date does not cover a language

**`left_out_languages(row)`**, **`window_created_max(row)`**: the languages that the end date of the retrieval left out, from its crawl dates in the index, and the window's bound on the creation date, which the step `gone` compares with GitHub's creation dates

**`sampling_frame_metadata(row, config, results, initial, final)`**, **`save_output(path, metadata, items)`**, **`parse_args`**, **`main(argv)`**: the output

**`read_license_report(path)`**, **`write_license_report(path, table)`**, **`check_licenses(report_path, licenses_path, osi)`**, **`run_license_check(report_path, licenses_path, spdx_path)`**: the license table and `--check-licenses`

### Output

`../data/sampling/ghs_filtered.json`:

- `_metadata.filtered_at`: UTC
- `_metadata.input_source`: `retrieval_id`, `downloaded_at` (the retrieval's start, which `4_data-analysis/rq2/_repo_metadata.py` takes as the day that GHS's counts describe), `item_count`, `window`, `query`, `ghs_version`, and `github` with the query's start and end, `found`, `not_found`, the repositories that GitHub did not find or blocks, and `unresolved`, the rows that the query left unresolved, which no response shows to be gone
- `_metadata.filter_config`, `_metadata.stages`, one entry per filter step (`stage`, the step's number, `key`, `description`, `removed`, `remaining`, `values`), `_metadata.final_count`. The values of the step `gone` are `unresolved`, `without_id` and `created_after_window`, the rows that it removed for each of these reasons. The values of the step `languages` are `top` (the number of languages), `languages` (the languages kept) and `left_out` (the languages that the end date of the retrieval left out and that the step would otherwise have kept, each with its crawl date or null)
- `items`: the sampling frame's rows, GHS's fields with GitHub's fields laid over them, and `ghsId`, `ghsName`, `githubStatus`

`../data/sampling/ghs_licenses.csv`: `license` (empty for no license), `repositories`, `previous_repositories` (blank when the previous table did not have the license), `osi_approved` (`TRUE` or `FALSE`), `decision` (`kept`, `excluded` or `not_osi_approved`), `reviewed` (`software`, `excluded` or empty) and `examples`, five repository names separated by semicolons

## Error handling & edge cases

| Scenario | Behavior |
|----------|-----------|
| No pointer, or the retrieval has no GitHub responses | `ERROR repository_filtering: The retrieval cannot be read. ...` naming the script to run first, `1_download_ghs.py` or `2_query_github.py`, exit 1, nothing written |
| GitHub's responses are for other rows or in another order | Rejected, exit 1 |
| A language that the step `languages` reaches in its ranking before it has kept its number of languages has a crawl date before the end date of the retrieval, or GHS returned no crawl date for it | `WARNING repository_filtering: Filter step 6 (languages) left out <language>, because the crawl date of <language>, <date>, is before the end date of the sampling window. Kept the next most common language in its place.` or `... because GHS returned no crawl date for <language>...`. The next most common language that the end date covers takes its place, `values.left_out` contains the language with its crawl date, and the sampling frame is written, exit 0 |
| The retrieval's crawl dates in the index are no JSON object | `ERROR repository_filtering: The retrieval cannot be read. The crawl dates of retrieval <id> in the index are not JSON...`, exit 1, nothing written |
| The retrieval's index row has no date YYYY-MM-DD as `created_max` | `ERROR repository_filtering: The retrieval cannot be read. The index row of retrieval <id> records the created_max '...', not a date YYYY-MM-DD.`, exit 1, nothing written |
| GitHub created the repository under GHS's name after the window's `created_max` | The step `gone` removes the row and counts it in `values.created_after_window`. A repository created on the day of `created_max` stays |
| A config key that the filter does not read | `ERROR repository_filtering: Could not read the config ...`, exit 1 |
| `config/spdx_licenses.json` is missing, unreadable, or names no license or no version | `ERROR repository_filtering: Could not read the reviewed licenses or the SPDX list (...).`, exit 1 |
| `--refresh-spdx` cannot fetch the list, or the list names no OSI-approved license | `ERROR repository_filtering: The SPDX list cannot be fetched (...).`, exit 1, the tracked list unchanged |
| A sampling frame filtered with `filter_licenses: false` | Every license is kept, and the table is written with `kept` for each. `--check-licenses` names every license of the table that the review does not list as software |
| `--check-licenses` over a table that names no license | `ERROR repository_filtering: The licenses cannot be checked (... names no license).`, exit 1 |
| GitHub reports no license or no primary language | The license or language step removes the repository |
| A write that fails | The previous sampling frame stays, because the filter writes the sampling frame under a temporary name and replaces the file in one step |
| A power loss during a write | The name holds the previous file or the new file, never an empty file that would stop the classification or the next filter. The sampling frame, the license table and the SPDX list are each synced to disk before the rename, and the directory after it (`caches.replace_file`) |
| A license that the sampling frame keeps and that `config/licenses.csv` does not cover | Kept, with a `WARNING` naming it. `--check-licenses` exits 2 until a row covers it |
| `config/licenses.csv` without a column, with an unknown decision, a row without a reason, source or date, or a license listed twice | Rejected, exit 1 |
| `--check-licenses` without a table | `ERROR repository_filtering: ... does not exist. Filter a retrieval first.`, exit 1 |

## Tests

See `test_filter_ghs.py`, which uses the standard library's `unittest`. The suite loads the script by path through `_script_loader.py`, which stubs `requests` and `yaml` where they are absent. It tests the filter steps over rows that it merges, runs the filter over a retrieval in a temporary cache, and tests the refresh of the SPDX list against a fake `requests.get`. The tests check that a file is synced before its rename by recording each call of the real `os.fsync` and `os.replace` (`_script_loader.synced_writes`).

- **`TestMerge`**: GitHub's response is what the sampling frame contains, and GHS's id and name stay; GitHub's description is copied, and None when GitHub has none; a row that GitHub does not have keeps GHS's values
- **`TestLicenseRules`**: a direct match and GitHub's spellings; a license name counts in either spelling; the allowed set is OSI minus exclusions minus the licenses below the percentile; the quantile interpolates as numpy does
- **`TestFilterSteps`**: two repositories under one name are both left out; gone removes what GitHub does not have, blocks or marks as private; gone removes the unresolved rows and counts them under their name; gone removes the repositories that GitHub found without an id, two created in one second among them, and counts them; gone removes a repository that GitHub created under GHS's name after the day of the window's `created_max`, also in the first hour of the next day, and counts it, while a repository that GitHub created late on the day of `created_max` stays; duplicates are one repository on GitHub and keep the current name, over the pairs of the GHS search result of March; repositories created in one second are not duplicates; without the current name the most commits, then the lowest GHS id win; cleanup reads GitHub's flags and can be narrowed or skipped; missing data; licenses read GitHub's license; languages keep the top N and a tie goes by name; languages rank only the languages that the end date covers, name and record each language that the end date left out and that ranks before the last language kept, and keep the next most common language in its place; without the language filter, the step keeps every language that the end date covers; educational matches topics and the current name; activity takes the absolute value over the quantile
- **`TestTheEducationalRules`**: every alternative of both educational patterns removes a hand-labeled educational repository of `../data/sampling/educational/labels.csv`, and nine in ten labeled removals are educational; dlib, concourse, discourse, MercuryWorkshop's and other owners' software stay; tutorials, courses, katas and example code go
- **`TestCopies`**: the repositories at one head commit, a personal copy created first and the project, all stay in the sampling frame
- **`TestARun`**: a run writes the sampling frame with its provenance and its eight filter steps; the record counts an unresolved row apart from the repositories that GitHub did not find; a repository that GitHub created after the window's `created_max` in the index row, under the name of a repository that GHS crawled in 2017, is not in the sampling frame and is counted under the step `gone`, while a repository whose creation times in GHS and GitHub differ only within the day of `created_max` stays; an index row without a date as `created_max` is rejected; a relative output path of the config is under the stage's data directory; a retrieval without GitHub's responses is rejected; responses out of step with the rows are rejected; a response without a field of the query is rejected; a dry run writes nothing; a larger `--top-languages` over a retrieval whose end date left out languages, with a crawl date before it or none, writes the sampling frame without them, names and records each, and keeps the next most common language that the end date covers; a language that ranks within the top N only after the cleanup step, which the download counted outside them, gives way to the next language that the end date covers, and the table of the filter steps and the README of the release name it; a retrieval without crawl dates leaves no language out; a crawl date on the end date is not left out; crawl dates that are no JSON are rejected; a config key that the filter does not read is rejected; the shipped config loads and reads the tracked SPDX list; skipped without `yaml`
- **`TestTheReviewedLicenses`**: an excluded OSI-approved license is removed and an unreviewed one kept and named; the examples are the same whatever the order and at most five; a review without a reason or with a license twice is rejected; the table records each license's count in the table that it replaces; the check names a kept license that nobody reviewed, a software license that the SPDX list does not mark as OSI-approved, and an OSI approval that the tracked list no longer gives; a reviewed sampling frame has no finding
- **`TestTheWrites`**: the sampling frame and the license table are each synced to disk before the rename and the directory after it
- **`TestTheLicenseCheck`**: a run writes the table and the check reads it, 2 for an unreviewed license and 0 once it is reviewed; without a table the check exits 1; a run reaches no network, records the list's version and the review's SHA-256, and removes the license that the review excludes; a review that no longer excludes a license that the sampling frame excludes requires another run of the filter; a dry run writes no table; a sampling frame that filters no license writes its table; a table that names no license cannot be checked; a flag that the check does not have exits 1 and not the 2 of a finding
- **`TestTheTrackedReview`**: every license that `config/licenses.csv` reviews as software is OSI-approved in the tracked SPDX list, and every row has a source
- **`TestTheStepOfTheRunner`**: the step `repository_filtering` of `run_sampling.py` produces first the sampling frame that the shipped config names, and it declares every file that the filter reads, the config, the review of the licenses and the SPDX list, and every file that it writes, the sampling frame and the license table; skipped without `yaml`
- **`TestTheSpdxList`**: a list without a license or a version, or no list, is rejected; a refresh writes the current list and names the approvals added and withdrawn, exit 2; the list is synced to disk before the rename and the directory after it; a refresh with the same approvals exits 0; a refresh that cannot fetch, or reads no license, changes nothing and exits 1; the shipped config reads the tracked list

Run with:

## Verification

1. After a run, `_metadata.stages` has the eight keys in order, the `remaining` of each filter step is the input of the step after it, and the last `remaining` equals `final_count` and the length of `items`
2. Every item has an `id`, no two items share one, and every item's `name` is the name that GitHub returned

## Known limitations

- An earlier version of this filter, with the ninth step `mirrors`, built the sampling frame of the run of all five stages that started on 2026-10-23, from retrieval `2026-10-23T074035Z`. That step left out the repositories that shared their head commit with a repository created earlier, and the current filter keeps them ([Key decisions](#key-decisions)). The sampling frame of 2026-03-17, which the archive held until 2026-10-29, came from an earlier version of the filter over the GHS search result of March, with GHS's ids and names, its 12-hour timestamps, duplicates keyed on name and creation time, and tied pairs decided by pandas' sort. The sampling frame of a published dataset comes from a retrieval of this stage
- The topics, the commit and watcher counts and the code metrics are GHS's values, as old as the repository's last crawl
- A run writes the sampling frame to `../data/sampling/ghs_filtered.json`, the path that the tracked sampling frame is extracted to, and replaces that sampling frame for every reader of the file. To restore it, extract `../data/sampling/ghs_filtered.json.7z` again, as `0_README.md` shows
