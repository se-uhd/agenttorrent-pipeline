# The cache of labels

## Context

`label_cache.py` keeps every decision that the classification made about a repository as plain files under `../data/classification/labels/`, so that a label is made once for a README and reused while nothing that decided it changed. A decision is a label, derived from the model's response for one README, or an exclusion, recorded for a README that the classification could not use. `1_classify_repos.py` writes the cache and reads it for reuse. `changed_labels.py` reads two runs from the cache and writes the comparison of the later run to it, and `2_evaluate_labels.py` reads the cache to compare two models.

## Key decisions

- **Language:** Python 3.14, in the single module `label_cache.py`, with the standard library and the package's `CLASSIFICATION_DIR` and `caches.sync_directory`. The cache uses no database, as the retrieval cache of the sampling stage uses none (`../1_sampling/ghs-cache-spec.md`)
- Each run writes one set of files, once: `<id>.decisions-001.jsonl.xz` and the parts after it, which contain the decisions that the run made, one JSON object per line, in the order in which the run made them. A run does not write again a decision that it reuses unchanged from an earlier run. A monthly run over a sampling frame with mostly unchanged READMEs therefore adds a small file and changes no existing file. The cache keeps labels permanently, because the label evaluation compares the labels of two models for one README, and a later label shows what changed only against an earlier label
- A run is named by the UTC second of its start, such as `2026-10-06T081500Z`, or by the first second after it that no run of the index has (`new_run_id`). `check_id` raises `CacheError` for any other id, so that an id never names a path outside the cache
- The index is read and written under an exclusive lock (`index_lock`), a `flock` on the cache's directory, which is never replaced. Without the lock, two runs at once, such as the runs of the two models over one check sample, would each read the index, change their own row and write the whole index, and the run that wrote last would undo the change of the other. `add_run` chooses the id of a new run and writes its row under one lock, and two runs started in the same second therefore get an id each
- A label is kept under the repository's GitHub id, the model and the key of the classification parameters (below). An exclusion is kept under the GitHub id and the key of the classification parameters, because no model decided it. The parameters name the classifying model with its weights, its quantization and the settings of its requests, and a run of another model therefore decides its exclusions again, from the README and the language check and without a request to a model. A label that the classifying model made at its higher temperature, or that the second model made, because the classifying model left the repository without a decision after the retry rounds and a failed response, names the run's classifying model as its model and records its settings under `higher_temperature` or `second_model`, with the kind and the error of the failed response after which it was made and, for a response that holds the text of a message instead of the checklist, the length, the start and the end of the text under `message`. A later run under the same model and parameters reuses it only when the run has the same higher temperature or second model (`classify-repos-spec.md`). A label that a model made at its own settings after a failed response at the repository, as a model without a higher temperature does, such as the second model or a model with `--endpoint-default-temperature`, records the first failed response of that model at the repository in the run under `first_failed_response`: its kind as `reason`, its `error` and, for a response that holds the text of a message instead of the checklist, the length, the start and the end of the text as `message`. In a label of the second model, the record of the second model holds the classifying model's last failed response, and `first_failed_response` the second model's own first failed response. The record names no setting, and neither `reusable` nor the comparison of the settings of the higher temperature and the second model (`Run.applies`) reads it, so a later run reuses the label as it would without the record. The language check is recorded with each decision and not among the parameters (`classify-repos-spec.md`). `Decisions` keeps the latest decision under each key: A decision of a later run replaces a decision of an earlier run, and within a run, a later decision replaces an earlier decision. `Decisions.load` keeps only the decisions that the run that loads them can reuse (`reusable`): the labels under its model and classification parameters and the exclusions under its parameters. The run looks up no other decision, and each decision keeps every tool output, so the decisions of the other models and parameters would hold every run of the cache in memory for the whole run, and each new set of parameters adds the decisions of a whole sampling frame. `origin` and `written` serve the decisions that the run reuses and the decisions that it makes, and `load` therefore keeps the origins of the decisions that it keeps alone. A renamed repository keeps its label, because GitHub's id stays the same across renames
- The classification parameters are recorded in full under the SHA-256 of their canonical JSON, with sorted keys, no whitespace and non-ASCII characters kept, as `parameters/<sha256>.json`. A label names its classification parameters by this hash, and `recorded` raises `CacheError` for a file with a SHA-256 that differs from its name
- Every lookup matches a recorded digest by its key (`ParameterKeys`): the digest of the parameters that the cache records under the digest, without the provider of a model (`without_provider`). The maintainer decided on 2026-11-04 that "the model, quantization, configuration should be part of, but not the [...] provider". The classification parameters record the model, the Hugging Face id of its weights, its quantization and every setting of its requests, and since that day no provider. Parameters recorded before name the provider of the classifying model, the summary model and, for a few records, the second model (`MODEL_BLOCKS`). Their key is the digest of the same parameters as the classification records them since, so that a run under the parameters without the provider reuses their labels and exclusions, their kept responses and the partial files of their runs, and resumes a stopped run under them (`1_classify_repos.same_run_key`). Parameters that differ in the model, the Hugging Face id, the quantization or any setting keep keys of their own. A digest without a record in the cache is its own key, because a run writes the record of its own parameters as it starts. The key needs no rewrite of a stored file: the decisions, the index and the partial files keep the digests that they were written with, the record of each digest stays where it is, and the entrypoint of the container needs no conversion of the data root. `Decisions`, `reusable`, `Decisions.kept`, `shared_parameters`, the resume of a run, the comparison with the previous run, the label evaluation and the estimate of the cost all compare digests by their keys. The tracked records name no provider, and each of their digests is its own key
- The index records a checksum of every decisions file, the SHA-256 of its compressed bytes, and a reader raises `CacheError` for a file that changed since it was written. A reader of the decisions or the comparison of a run (`read_decisions`, `read_changes`) computes the checksum of each part in a first pass over the open file, and raises `CacheError` for a part with another checksum before it reads any of its lines. In a second pass, it decompresses the part one line at a time and holds only the state of the decompressor and one line, besides what `Decisions.load` keeps. Every run reads every part of the cache (`Decisions.load`), and a part keeps every tool output of its decisions. Decompressed whole, the text of a part would take four bytes a character once one character is outside ASCII, and its lines as much again. A run that stopped or failed writes the decisions that it made so far, and later runs read them as they read the decisions of a finished run. A run that is still running, or that a kill ended, has no checksum, and only its partial file can be read (below)
- Every file except a partial file is written whole under a temporary name, synced to disk and renamed, and the cache's directory is synced after the rename (`agentcontext.caches.sync_directory`), as for the collection's caches. If a power loss came after a rename had reached the disk but before the data had, the name would hold an empty or truncated file, and an index that `read_index` cannot read stops every later run. `agentcontext.caches.replace_file` writes text, and the compressed files are bytes, so `label_cache.py` writes these files itself (`_write_whole`). A partial file grows by one line at a time (`end_partial`, below)
- A run's decisions are split into parts that each stay under <!--s:parameters.2_classification.label_cache.MAX_FILE_BYTES.mb-->95<!--/s--> MB, below GitHub's limit of <!--s:github.file_size_limit_mb-->100<!--/s--> MiB for a file. A decision keeps every tool output, and the outlines of the files take most of its bytes after compression ([the record of the calibration](../docs/history/2026-10-classification-calibration.md), rules 13 and 14). Run `2026-10-23T093036Z` over the <!--s:classification_2026_10_23.repositories-->46,187<!--/s--> repositories in the sampling frame of retrieval `2026-10-23T074035Z` wrote a part of <!--s:classification_2026_10_23.decisions_001_mb-->67<!--/s--> MB and a part of <!--s:classification_2026_10_23.decisions_002_mb-->66<!--/s--> MB. `write_decisions` compresses the whole run and, while a part is too large, compresses each half of the part instead. The parts then follow the order of the decisions, and the size of each part is measured rather than estimated. It also removes every part beyond the last part that it wrote, which an earlier attempt to write the same run left, so that the files on disk are the parts that the index names. A single decision that is too large for a file raises `CacheError`
- A finished run also writes the outcome of every repository that it covered to `<id>.labels.csv.xz`, with the run that made each decision, because a reused decision is in an earlier run's files and the decisions files alone do not record which label a run gave. `changed_labels.py` reads two runs' labels files to compare them (`changed-labels-spec.md`)
- A finished run that left a repository without a decision after the model's response, because GitHub failed for its facts, writes that response to `<id>.kept.jsonl.xz` under the key of `Classifier.kept` (`write_kept`). `Decisions.kept` returns the responses that the other runs under one model and classification parameters kept, from their kept files and their partial files, so that a later run pays the model only once for the same input. The index records no checksum of the file, and `read_kept` reads a file that fails the check of its xz container as empty. A response that a later run does not find only costs another request to the model, whereas a label would be derived from a damaged response
- The index records each run's scope: `sampling_frame` for a run over the whole sampling frame, and `repository_list` or `limit` for a run over part of it. `previous_run` returns the last finished run over a sampling frame before a given run, and a comparison therefore never compares a run with a run of a label evaluation or a trial
- The comparison of a run is written in parts, as its decisions are, to `<id>.changes-001.jsonl.xz` and the parts after it, with the checksum of each part in the index. While the comparison is in progress, it is written to `<id>.changes.partial.jsonl`
- `<id>.tokens.csv` contains the tokens of a run by the tier that OpenAI billed or by the provider that served an OpenRouter model, its pinned provider or its backup provider, and for an OpenRouter model the columns of the tiers hold the provider slug of the endpoint that served the responses. Its columns are `TOKEN_COLUMNS`: the role of the model (`classifying_model` or `summary_model`), the model that the requests named, the service tier that they named, the service tier that their responses reported, empty for a response that reported none, and the requests, input tokens, cached tokens, cache writes, output tokens and reasoning tokens. The index sums the tokens of a run without their tier and without telling apart the cache writes, which OpenAI bills at prices of their own, and its columns stay as they are, because a new column would change the stored format of the index. Each invocation of a run and of its comparison adds the tokens of its responses once, as it ends (`add_tokens`), under the lock of the index, so that two invocations that end at once both count. An invocation that a kill ends adds nothing, and the cost record prices what the index counts beyond the file at an assumed tier (`costs-spec.md`). The index records no checksum of the tokens file, because the file changes after the run's row is written, when the comparison adds its tokens
- The cost record of a run, `<id>.cost.csv`, is written by `costs.py` from the index, the tokens file and the prices, and it can be written again at any time from these. No reader of the cache reads it
- A run in progress appends its decisions to `<id>.partial.jsonl`, which `.gitignore` excludes. The first line names the repositories that the run covers, and each repository that the run failed gets a line as well, which for a failed response records its kind, the counts and tokens of the failed attempts and each failed attempt with its temperature and top_p and the start and the end of the arguments of a malformed checklist or of the text of a message that the model wrote instead of the checklist, and while the second model labels also the classifying model's failed attempts. `1_classify_repos.py` writes and reads the partial file (`classify-repos-spec.md`)
- `Decisions.load` also reads the decisions in the partial file of every running or incomplete run other than the run that loads them, through the reader of a partial file that `1_classify_repos.py` passes as `partial`. A run that a kill ended wrote no decisions file, and a run over another sampling frame or scope does not resume it. Without the decisions of its partial file, the model would label its repositories again. A run reuses such a decision as any other decision and writes it to its own decisions file, and `written` tells it apart from a decision that a decisions file already contains. `origin` names the run of the decisions file that contains a decision, whether `load` reads the partial file before or after that decisions file. For example, a stopped run that resumes and reuses a decision from the partial file of a killed run writes the decision to its decisions file. A later run that reuses the decision then names the resumed run in its labels, and `decisions_of` reads the decision from the decisions file of the resumed run
- Only `\n` ends a line, in a part of a run's decisions or comparison and in a partial file. A JSON string written with `ensure_ascii=False` keeps U+2028, U+2029 and U+0085 as they are, and `str.splitlines` ends a line at each of these characters. If the lines were split at these characters, a decision with one of them in its justification would be missing when its partial file is read back, and the decisions file of the run would lack the decision. A reader would also raise `CacheError` for a decisions file that contains one of these characters, as not JSON
- A line of a partial file that a stop cut short is dropped before the next line is appended (`end_partial`). Appended to the cut line, the next decision would be read back as part of that line and dropped with it
- Every reader of a partial file reads it in binary, one line at a time (`partial_lines`), and leaves out a last line without its `\n` and a line that is not JSON. `end_partial` repairs only the partial file of the run that appends to it. `Decisions.load` also reads the partial files of other running or incomplete runs, in which a kill can have cut the last line inside a character of UTF-8, or a running run can be writing the last line. Decoding such a file whole would fail and stop every later run. A partial file keeps every tool output, and a reader holds one line at a time for the reason given above for the parts of the decisions. A reader that names the statuses that it needs parses only the lines with these statuses. It reads the status of a line from its head, which the run and the comparison write as `{"id":N,"status":"..."`. A line with another head is parsed and filtered by its status

## Module: `label_cache.py`

### Index columns

The index has the columns `run_id`, `started_at`, `finished_at`, `outcome` (`running`, `incomplete` or `finished`), `model`, `parameters`, `retrieval_id`, `scope` (`sampling_frame`, `repository_list` or `limit`), `repositories`, `labeled`, `excluded`, `reused`, `gone`, `github_requests`, `model_requests`, `input_tokens`, `cached_tokens`, `output_tokens`, `reasoning_tokens`, `summary_input_tokens`, `summary_output_tokens`, `decisions`, `decisions_sha256`, `labels_sha256`, `compared_with`, `label_changes` and `changes_sha256`. `decisions_sha256` contains the SHA-256 of each part of the run's decisions in order, separated by spaces, and `labels_sha256` the SHA-256 of the labels file. `compared_with` names the previous run. Run `2026-10-06T140917Z` was compared with the batch classification of March 2026, paired by repository name, and its `compared_with` is `batch-2026-03`. `label_changes` counts the repositories with a changed outcome, and `changes_sha256` contains the checksums of the comparison's parts. The requests and tokens are summed from what each line of the run's partial file records, and include the comparison's requests and tokens, summed from the comparison's partial file in the same way (`Spending`, `spent_in`). The tokens of the classifying model and of the model that summarizes pages are counted separately, because the two can be different models at different prices.

### Function structure

**`utc_now()`**, **`iso(moment)`**, **`run_id(moment)`**, **`new_run_id(cache_dir, now)`**, **`add_run(values, cache_dir, now)`**, **`check_id(value)`**: times and run ids, and a new run's row

**`canonical(value)`**, **`digest(value)`**, **`record(kind, value, cache_dir)`**, **`recorded(kind, sha, cache_dir)`**: classification parameters by their hash. **`without_provider(value)`**, **`ParameterKeys(cache_dir)`**, **`MODEL_BLOCKS`**, **`PROVIDER`**: recorded parameters without the provider of any model, and the key of a digest, the digest of its record without the provider, by which every lookup matches it. **`shared_parameters(cache_dir, parameters, known)`**: the digest of recorded parameters without the block of the classifying model, `classifying_model`, and without the provider of any other model, under which the label evaluation compares two models and the comparison tells a changed model from changed parameters. For parameters recorded without that block, the digest covers all of the parameters but the provider

**`decisions_path(cache_dir, rid, part)`**, **`partial_path`**, **`write_decisions(cache_dir, rid, decisions)`**, **`read_decisions(cache_dir, rid, checksums)`**: a run's parts

**`labels_path(cache_dir, rid)`**, **`write_labels(cache_dir, rid, rows)`**, **`read_labels(cache_dir, rid, checksum)`**: the outcome of every repository in a run, in `LABEL_COLUMNS`, which are `id`, `repo_name`, `outcome` (`labeled`, `excluded`, `gone` or `undecided`), `label`, `reason` and `decided_in`. A repository that the run left without a decision (`UNDECIDED`) has no decision and no `decided_in`, and its reason names what failed and the error

**`kept_path(cache_dir, rid)`**, **`write_kept(cache_dir, rid, kept)`**, **`read_kept(path)`**: the model's responses that a finished run kept for its undecided repositories

**`tokens_path(cache_dir, rid)`**, **`read_tokens(cache_dir, rid)`**, **`add_tokens(cache_dir, rid, billed)`**, **`cost_path(cache_dir, rid)`**: the tokens of a run by role, model and service tier in `TOKEN_COLUMNS`, with the roles `CLASSIFYING_MODEL` and `SUMMARY_MODEL`, the tokens of an invocation added to them, and the place of the run's cost record

**`changes_path(cache_dir, rid, part)`**, **`changes_partial_path`**, **`write_changes`**, **`read_changes`**: the comparison of a run, in parts

**`previous_run(cache_dir, rid)`**, **`decisions_of(cache_dir, wanted)`**: the run that a run is compared with, the decisions that a comparison names, and `CacheError` when a named run contains no decision for a repository

**`partial_lines(path, statuses)`**, **`end_partial(path)`**: the lines of a partial file with the statuses that a reader needs, read one at a time, and a partial file without a last line that a stop cut short

**`Spending`**, **`spent_in(path, keys)`**: what a run or a comparison spent since the last line of its partial file, and the sum that the lines record

**`read_index(cache_dir)`**, **`put_index_row(values, cache_dir)`**, **`index_lock(cache_dir)`**, **`all_decisions(cache_dir)`**: the index, changed under its lock, and the decisions of every run that wrote them

**`reusable(decision, model, parameters, keys)`**: whether a run of a model under classification parameters can reuse a decision, with the parameters compared by their keys

**`Decisions`**: the latest decision per key, with the parameters by their keys, through these methods:

- `add`, `latest`, `label` and `exclusion`
- `load(cache_dir, model, parameters, partial, skip)`: the decisions that a run of `model` under `parameters` can reuse
- `kept`: the responses that other runs kept
- `origin`: the run with the decisions file that contains a decision, or the run in progress that writes it, else the run of the partial file that contains it
- `written`: whether a decisions file contains a decision or the run in progress made it

`RESUMABLE` names the outcomes of a run for which `load` reads the partial file

## Error handling & edge cases

| Scenario | Behavior |
|----------|-----------|
| A run id that is not a UTC time to the second | `CacheError` |
| A decisions, labels or changes file, or recorded classification parameters, changed on disk | `CacheError` |
| An index with other columns, or a value for a column that it lacks | `CacheError` |
| A run's decisions of <!--s:parameters.2_classification.label_cache.MAX_FILE_BYTES.mb-->95<!--/s--> MB or more after compression | Written in as many parts as keep each under <!--s:parameters.2_classification.label_cache.MAX_FILE_BYTES.mb-->95<!--/s--> MB |
| One decision of <!--s:parameters.2_classification.label_cache.MAX_FILE_BYTES.mb-->95<!--/s--> MB or more after compression | `CacheError`, and nothing is written |
| A run that stopped, with an index row and no file | `Decisions.load` reads none of its decisions, unless it is given the reader of a partial file and the partial file of the run exists |
| A run's labels name it as the run that decided a repository, and its decisions contain no decision for the repository | `CacheError` |
| A tokens file with other columns, or with a count that is not a whole number | `CacheError` |
| A run without a tokens file | `read_tokens` returns no rows |

## Tests

See `test_label_cache.py`, which uses the standard library's `unittest`. Every test case writes into its own temporary directory.

- **`TestFiles`** (17): decisions are read back as written; two runs that update their rows at once keep both updates; two runs started at once in one second get an id each; a decision with a line separator in a string is read back whole; a line that a stop cut short is dropped before the next is appended; a partial file is read by status without a line that a stop cut short inside a character; a changed file is refused; a part that does not match its checksum yields none of its decisions; a part is read one line at a time; a run id is the UTC time of its start; two runs started in one second get an id each; classification parameters are recorded under their hash once; the index keeps one row per run in run order; a rewrite of the index, the labels or the decisions is synced to disk under a temporary name while the old file stays whole, replaces the old file by a rename, and syncs the directory before it returns, with the real `os.fsync` and `os.replace`; a run past the limit is split into parts under it; a rewrite with fewer parts removes the rest; one decision past the limit is refused
- **`TestDecisions`** (7): a later run replaces an earlier decision under the same key; labels are kept apart by model and classification parameters; only the decisions that the run can reuse are held, from decisions files and from the partial file of a killed run, with their origins, and the other set of parameters holds its own decisions alone; the latest is the more recent of label and exclusion; an exclusion stands for every model under its classification parameters; a run without a decisions file is not read; the partial file of a killed run is read in run order and its decisions are told apart from the written ones
- **`TestParameterKeys`** (3): parameters recorded with the provider have the key of the same parameters without it, also for another provider, a digest without a record is its own key, and the shared digests of both agree; parameters that differ in the model, the weights, the quantization or a setting of either model have keys of their own; a run under the parameters without the provider loads the decisions of a decisions file and of the partial file of a killed run and the kept responses under the parameters with it, and a run under other parameters loads none of them
- **`TestKeptResponses`** (3): the responses of the runs under the same model and classification parameters are read, from a finished run's kept file and from the partial file of a running or incomplete run; a kept file that fails its check is read as empty; no response to keep removes the file
- **`TestRunLabels`** (6): a run's labels are read back as written; a changed labels file is refused; the previous run is the last finished run over a sampling frame before a run; the comparison is written in parts as the decisions are; a decision names the run that made it; a decision that the named run does not contain is refused
- **`TestTokens`** (2): each invocation adds its tokens to the run's tokens file, one row per tier in the order of the rows' keys, with LF line endings, and a run without the file has no rows; a tokens file with other columns is refused

Run with:

```shell
python3 -m unittest test_label_cache -v
```
