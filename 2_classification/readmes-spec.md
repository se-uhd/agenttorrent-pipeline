# Read a README through GitHub's API

## Context

`readmes.py` reads the README of a repository in the sampling frame for the classification (`classify-repos-spec.md`) and determines whether the classification can use it. The batch classification cloned every repository to read its README. GitHub's README API returns the README alone, without a clone, and returns 304 for a request that sends the ETag of a README that did not change.

## Key decisions

- **Language:** Python 3.14, in the single module `readmes.py`, with `requests` for HTTP, `lingua` for the language and `agentcontext.github_api` for the pool of GitHub access tokens and the reading of a rate limit
- The classification reads the README that GitHub shows. `GET /repos/{owner}/{repo}/readme` returns it, and GitHub looks for it in this order: "If a repository contains more than one README file, then the file shown is chosen from locations in the following order: the `.github` directory, then the repository's root directory, and finally the `docs` directory" ([About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes))
- The README is read at the commit that the sampling frame recorded, `?ref=<lastCommitSHA>`, so that the label records the revision that it was decided on and the outline of the files in the input describes the tree at the same commit
- A README unchanged since the last decision costs no request against the rate limit. The request sends the ETag of the latest decision on the repository in `If-None-Match`, and GitHub states that "Making a conditional request does not count against your primary rate limit if a `304` response is returned and the request was made while correctly authorized with an `Authorization` header" ([Best practices for using the REST API](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api))
- Content up to <!--s:github_api.contents_json_limit_mb-->1<!--/s--> MB comes in the JSON response, and `fetch` requests larger content through the raw media type. The contents API supports all its features for a file of "1 MB or smaller", and between <!--s:github_api.contents_json_limit_mb-->1<!--/s--> and <!--s:github_api.contents_raw_limit_mb-->100<!--/s--> MB "Only the raw or object custom media types are supported" ([Get repository content](https://docs.github.com/en/rest/repos/contents#get-repository-content)). `fetch` decodes the text as UTF-8, replaces the bytes that are not UTF-8 and removes a byte-order mark
- GitHub returns 404 for a repository without a README, for a repository that it does not have, and for a commit that the repository no longer has, as after a force push. After a 404, `fetch` requests `GET /repos/{owner}/{repo}` to tell these cases apart. When that request returns 404 or 451, or GitHub blocks access to the repository (`github_api.blocked`), the README is `gone`. When the response names another GitHub id, the name belongs to a different repository, created after the repository in the sampling frame was deleted, and the README is `gone` too. When the repository has a new name, `fetch` reads the README again under that name. When the repository exists and the README request named a revision, `fetch` reads the README at the default branch and records no revision. When the README request named no revision, the outcome is `no_readme`. A 451 or a block in response to the README request itself also makes the README `gone`
- Requests go through the pool of GitHub access tokens (`Client`). The pool pauses every GitHub access token of an account that reaches a rate limit and drops a GitHub access token that GitHub rejects (`../docs/credentials.md`). After HTTP 401, the client requests `/rate_limit` with the same GitHub access token, which costs nothing against the rate limit, and drops the GitHub access token only when GitHub returns 401 there too (`refused`). Otherwise the 401 counts as a failed attempt. The client keeps the GitHub access token because GitHub can return HTTP 401 for a GitHub access token that it still accepts. A pool that dropped a GitHub access token at each such response could be left empty, which would stop the run and, in the MCP server, leave every tool without GitHub. The client makes <!--s:parameters.2_classification.readmes.ATTEMPTS:words-->four<!--/s--> attempts after a server error or a failed request, with waits of <!--s:parameters.2_classification.readmes.WAITS.first-->10<!--/s-->, <!--s:parameters.2_classification.readmes.WAITS.second-->30<!--/s--> and <!--s:parameters.2_classification.readmes.WAITS.third-->60<!--/s--> seconds between them. Up to `MAX_PAUSES` pauses for a rate limit do not count as failed attempts. The client returns a 403 without the signs of a rate limit to the caller unchanged
- GitHub can also reject valid GitHub access tokens for a while, at `/rate_limit` too. Once GitHub has rejected every GitHub access token of the pool, the next request waits for each of `RECHECK_WAITS` in turn, which grow from minutes to hours, and checks the configured GitHub access tokens again after each wait. The pool continues with the GitHub access tokens that GitHub no longer rejects (`Client._refill`). The waits are the `ROUND_WAITS` of the sampling stage's query in `../1_sampling/2_query_github.py`, so that a period of rejections that ends within them does not end a run that takes days. One request makes the checks, and the requests of the other workers wait for its result. Only when GitHub rejects every GitHub access token after the last wait does the request raise `NoTokens`, which stops the run. Every later request then raises `NoTokens` at once, so that the other workers do not wait through the checks again
- A README that the classification can use has text and is in English. The language check reads the README that GitHub shows. A missing README, or a README that is empty or only whitespace, is an exclusion (`unusable`). The language check is the check of the batch classification. `prose` removes code, images, link targets, HTML tags, tables and badge lines, which are the lines that name shields.io, a badge, Travis CI or a `github.com/<owner>/<repo>/actions` link. From the rest, `language` reads the number of characters, the share of them that is ASCII, the number of letters, the language that Lingua detects and the confidence that Lingua gives English. `english` decides from these measures. Prose without characters is English. Prose with at least <!--s:parameters.2_classification.readmes.ASCII_ENGLISH.percent-->90%<!--/s--> ASCII is English. Prose with fewer than <!--s:parameters.2_classification.readmes.MIN_LETTERS-->60<!--/s--> letters is also English when Lingua names English or gives it a confidence of at least <!--s:parameters.2_classification.readmes.SHORT_ENGLISH_CONFIDENCE-->0.50<!--/s-->, or when the prose has at least <!--s:parameters.2_classification.readmes.SHORT_ASCII_ENGLISH.percent-->85%<!--/s--> ASCII. Longer prose is also English when Lingua names English or gives it at least <!--s:parameters.2_classification.readmes.MIN_ENGLISH_CONFIDENCE-->0.70<!--/s-->, or when Lingua names no language and the prose has at least <!--s:parameters.2_classification.readmes.SHORT_ASCII_ENGLISH.percent-->85%<!--/s--> ASCII. A decision records what `language` read, so that the check can be computed again under other thresholds
- The thresholds were measured against the model's judgment (rule 2 of [the reading rules](0_README.md#the-reading-rules)). Over the <!--s:calibration.readmes_with_text-->2,277<!--/s--> READMEs of the calibration sample, the check excluded <!--s:calibration.language_check.excluded-->65<!--/s-->, all of which the model judged not mainly English, and let through <!--s:calibration.language_check.let_through_not_english-->14<!--/s--> that the model judged not mainly English. The classification labels these READMEs `false` from the model's count of their words by language (`readme_words_by_language`). The ASCII rule keeps <!--s:calibration.english_misread_by_lingua-->13<!--/s--> English READMEs that Lingua alone misreads, such as gchq/CyberChef as Yoruba. `language_check` returns the thresholds with the version of Lingua, and each decision records them. The thresholds are not among the classification parameters. After a new version of Lingua, the classification therefore checks the language of the READMEs again without the model (`classify-repos-spec.md`)

## Module: `readmes.py`

### Function structure

**`Client`**: requests through the pool, with these members:

- `get(url, accept, etag)`
- `query(query, variables)` for one query of GitHub's GraphQL API
- `refused(token)`, whether GitHub also returns HTTP 401 for the GitHub access token at `/rate_limit`
- `responds()`, whether GitHub returns a usable response to the README request that it served last. `fetch` records that request through `served(url, etag)`, and `responds` sends it again with the README's ETag and with the attempts of `get`. GitHub returns HTTP 304 to it at no cost against the rate limit. Before the client has served a README, `responds` requests `GET /rate_limit` instead
- `served_earlier(name, decision)`, which records the README request of an earlier decision as the request of `responds` while the client has served no README
- `requests`, the requests made, and `responses`, the responses that the client passed on. A failed request, HTTP 5xx, a rate limit and the response to the request of `responds` do not count among `responses`. The pause for GitHub in the classification reads `responses` to end its pauses (`GitHubPause` in `classify-repos-spec.md`)

`GitHubPause` of the classification calls `responds` when GitHub fails a repository on its own. `responds` sends a README request because a README request reads the files of a repository and fails in an outage of GitHub's storage of repositories, as the other README requests do. `/rate_limit` reads no repository, and GitHub can respond to it while it fails every README request. The response to the request of `responds` does not count among `responses`. If it counted while GitHub fails the requests for every other README, each failure of another repository would be the first since GitHub's last response, and the pause would never begin.

`configured` names the GitHub access tokens that `_refill` checks again once the pool is empty, by default the GitHub access tokens of the pool. The review of the label evaluation passes an empty list, so that a reviewer who waits for the page sees the error at once.

A GraphQL response does not update the count of the REST API's requests in the pool, because the GraphQL API has a rate limit of its own. GitHub reports an exhausted GraphQL rate limit with HTTP 200, an error of type `RATE_LIMITED` and no data. `query` waits it out as `get` waits out a rate limit: It sends the query with another GitHub access token, or waits for the reset that the response names, while the requests to the REST API go on. If `query` returned the error as the response, the classification would read it as a mirror that merged no pull request.

**`check_token(session, value)`**, **`accepted_tokens(tokens, session, sleep)`**: the check of one GitHub access token against `/rate_limit`, with its verdict, and the GitHub access tokens that GitHub does not reject. Only HTTP 401 rejects a GitHub access token, as in the sampling stage's query. When a check fails on the network, or returns HTTP 5xx or a rate limit, `accepted_tokens` checks again after each wait of `CHECK_WAITS`, the waits that the query uses for the same check. It keeps a GitHub access token that no check reaches. If such a check dropped GitHub access tokens, a minute without the network at the start of a run would remove every GitHub access token, and the run would end before its first request

**`readme_url(name, revision)`**, **`fetch(client, name, repository_id, revision, etag)`**: one README, as a `Readme` with its status (`found`, `unchanged`, `no_readme`, `gone`), name, revision, path, blob SHA, ETag, size and text

**`repository(client, name)`**: GitHub's response for the repository, `GET /repos/{owner}/{repo}`, which has the creation time from which `forks.py` counts a fork's own commits (`forks-spec.md`), or `NoResponse` for any status but 200

**`unusable(readme)`**: the reason why a README cannot be used before its language is checked (`no_readme_found`, `empty_readme`, `not_found_or_no_access`), or `""`

**`wording(text)`**: the SHA-256 of the lowercase words of a README without badges, images, link targets, reference definitions, HTML comments and tags, bare URLs and numbers. Two READMEs with the same wording share one label (`classify-repos-spec.md`). A tag is a name and its attributes up to its `>`, which may span a line break but not a blank line. A `<` before a letter in prose, as in `a<b`, or in code, as in `i<n`, is not a tag, and the words after it count

**`names_language(name)`**: whether a name in the model's count of words by language names a natural language, which `mainly_english` of the classification tests when the count names no English for a README that Lingua measures as English. The name is one of the languages that Lingua supports, by its English name or its ISO 639-1 or 639-3 code, with or without a qualifier in parentheses or a script or a region, such as `zh-Hans`, or one of the names that the model's counts use for a language under a name that Lingua does not list (`OTHER_LANGUAGE_NAMES`)

**`prose(text)`**, **`detector()`**, **`lingua_version()`**, **`language_check()`**, **`language(text)`**, **`english(measures)`**: the language check. The classification excludes a README that the check finds not in English as `readme_non_english`. `lingua_version` reads the installed version once per process, because the check of every reused decision records it

## Error handling & edge cases

| Scenario | Behavior |
|----------|-----------|
| A rate limit | Every GitHub access token of the account pauses, and the request goes to another account's GitHub access token |
| A reached GraphQL rate limit, HTTP 200 with an error of type `RATE_LIMITED` | That GitHub access token is not used for a GraphQL query until the reset that the response names. The query goes to another GitHub access token or waits |
| A GraphQL response with `errors` that are not objects, such as a proxy's text | Not a rate limit (`github_api.graphql_errors` reads such a value as the message of an error object). `query` returns the response to its caller, which fails the repository |
| HTTP 401, and HTTP 401 again at `/rate_limit` with the same GitHub access token | The GitHub access token is dropped |
| GitHub has rejected every GitHub access token of the pool | `WARNING readmes: GitHub rejects every GitHub access token (HTTP 401). Checking them again in ... minutes.` before each wait of `RECHECK_WAITS`. The pool continues with the configured GitHub access tokens that GitHub does not reject. After the last wait without such a GitHub access token, `NoTokens`, and every later request raises it at once |
| The check of a GitHub access token before the first request fails on the network, or returns HTTP 5xx or a rate limit | Checked again after each wait of `CHECK_WAITS`, and kept when no check returns a verdict |
| HTTP 401 for a GitHub access token that GitHub accepts at `/rate_limit` | A failed attempt, and the GitHub access token is kept |
| A server error or a failed request <!--s:parameters.2_classification.readmes.ATTEMPTS:words-->four<!--/s--> times, or another status | `NoResponse` |
| The raw content of a large README fails | `NoResponse` |

## Tests

See `test_readmes.py`, which uses the standard library's `unittest`. A fake session stands in for GitHub and returns the response that a map assigns to each URL, and the pool runs on a fake clock. The language check runs Lingua itself.

- **`TestFetch`** (9): a README is read at the revision with its path, SHA and ETag; an ETag is sent and a 304 is unchanged; a README over <!--s:github_api.contents_json_limit_mb-->1<!--/s--> MB is read through the raw media type; a 404 with the repository there is no README; a 404 without the repository is gone; another repository under the name is gone; a renamed repository is read under its new name; the README of a revision that the repository lost is read at the default branch; a blocked repository is gone
- **`TestRepository`** (2): the repository has its description and creation time; a repository for which GitHub returns no response is `NoResponse`
- **`TestClient`** (13): a rate limit pauses the account and the request goes to another; a GitHub access token that GitHub refuses for its rate limit too is dropped; a GitHub access token that GitHub accepts for its rate limit is kept; a request that depends on no repository tells whether GitHub responds, and its response is not counted among the responses; server errors are retried and then raise `NoResponse`; a GraphQL query is posted and leaves the REST API's count alone; an exhausted GraphQL rate limit is waited out and leaves the REST API alone; a GraphQL response with errors that are not objects is passed on without a wait; a 403 without the signs of a rate limit is returned unchanged; the accepted GitHub access tokens leave out a refused GitHub access token; a check without a verdict, HTTP 503 or a failed connection, is made again and keeps the GitHub access token; a spell in which GitHub rejects every GitHub access token is waited out, and the requests continue with the GitHub access tokens that GitHub accepts again; a GitHub access token that GitHub rejects through every wait raises `NoTokens` after the last, and a later request raises it at once
- **`TestUsable`** (2): a README with text is usable until its language is checked; an empty, missing or gone README is not usable
- **`TestTheLanguageCheck`** (9): which names in a count name a language; a name with a run of underscores is read in time; an English README is English; a README in another script is not; code and tables do not decide the language; a language written in ASCII passes and the measures name it; a README without prose is English; a line of thousands of github.com links is read in time; a badge line is left out of the prose
- **`TestTheWording`** (3): badges, images, link targets, comments, whitespace and numbers are left out of the wording; one word more is another wording; a tag ends within its paragraph
- **`TestTheCalibrationMeasurementOfAReadme`** (2): the calibration diagnostic measures an English README as usable and records its language; it measures a README that is not mainly English as such

Run with:

```shell
python3 -m unittest test_readmes -v
```

## Known limitations

- A README in another language written in ASCII, such as German without umlauts, passes the check, because the prose is ASCII to <!--s:parameters.2_classification.readmes.ASCII_ENGLISH.percent-->90%<!--/s-->. Such a README costs one request to the model. The model's response states that the README is not mainly English, and the classification labels it `false`, as it did for <!--s:calibration.language_check.let_through_not_english-->14<!--/s--> of the <!--s:calibration.readmes_with_text-->2,277<!--/s--> READMEs of the calibration sample
