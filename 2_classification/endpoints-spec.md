# The services and endpoints that the classification calls

## Context

`endpoints.py` decides where the classification calls a model, with which settings of its requests, and how it reads the refusals and the credit of the service. The classification calls an OpenAI model through OpenAI's Responses API and an open-weight model, such as the default classifying model, through OpenRouter on one pinned provider and quantization. `1_classify_repos.py`, `classification_tools.py`, `changed_labels.py` and `costs.py` import the module.

## Key decisions

- **Language:** Python 3.14, in the single module `endpoints.py`, with the SDK `openai` for the clients, `urllib` for the credit of a key and the endpoint list of a model, and the package's `credentials`
- A model with an id that names its author, as OpenRouter's ids do (`deepseek/deepseek-v4.1-flash`), is an OpenRouter model, and any other model, such as `gpt-6-luna`, is an OpenAI model. OpenAI's model ids name no author. An OpenRouter model is called through OpenRouter's OpenAI-compatible Responses API at `https://openrouter.ai/api/v1`, with the first OpenRouter API key, and an OpenAI model through OpenAI's API, with the first OpenAI API key (`client`)
- An OpenRouter model is called on one endpoint (`Endpoint`): the provider slug of the endpoint as OpenRouter's endpoint list gives it in `tag`, such as `morph/fp8`, and its quantization. A provider can serve one model on several endpoints, such as DeepInfra's `deepinfra/fp8` and `deepinfra/fp8/flex` at two prices, and OpenRouter's provider routing matches the whole slug: "To target a specific variant or region, use the full slug including the suffix" ([provider routing](https://openrouter.ai/docs/features/provider-routing)). Every request routes to that endpoint with `order`, `allow_fallbacks: false`, `quantizations` and `require_parameters: true` (`Endpoint.routing`), so that OpenRouter never serves it at another provider or quantization and never on an endpoint that ignores a parameter of the request, such as the tools
- The Hugging Face id names the weights that the model id stands for. OpenRouter's model list gives it in `hugging_face_id`, such as `deepseek-ai/DeepSeek-V4.1-Flash`. The model id, the Hugging Face id and the quantization are classification parameters (`Endpoint.parameters`), so that a run of other weights or in another quantization labels again. The provider slug is none: The maintainer decided on 2026-11-04 that <!--maintainer-->"the model, quantization, configuration should be part of, but not the [...] provider"<!--/maintainer-->. `Endpoint.of` reads the provider of a block recorded before that day, and `with_provider` gives a block recorded since, which names none, the provider of the pinned record of the same model id, Hugging Face id and quantization, on which the comparison with the previous run repeats its labels and the cost record prices the tokens beyond the tokens file. An OpenRouter model needs a Hugging Face id, a provider slug and a quantization, and an OpenAI model takes none of them (`endpoint`). The quantization is one of the values of the provider routing: `int4`, `int8`, `fp4`, `mxfp4`, `nvfp4`, `fp6`, `fp8`, `mxfp8`, `fp16`, `bf16`, `fp32` and `unknown`
- Each pinned model has a backup provider of the same weights in the same quantization, with the same settings (`BACKUPS`, `backup_of`): `deepinfra/fp8` for DeepSeek V4.1 Flash and `gmicloud/fp8` for GLM-5.3, which the maintainer chose from a check of the backup providers on 2026-11-04. The maintainer decided on 2026-11-04 on a backup provider for the same model, rather than a key of the pinned provider at OpenRouter: <!--maintainer-->"Only the backup endpoint"<!--/maintainer-->. `Providers` decides which provider serves the next request of a model: the pinned provider while it serves, the backup provider after `switch`, and one request every <!--s:parameters.2_classification.endpoints.PINNED_CHECK_SECONDS.minutes:words-->ten<!--/s--> minutes (`PINNED_CHECK_SECONDS`) to the pinned provider as a test during the switch, also while an earlier test is in flight, so that a test that never reports holds back no further one. A response of the pinned provider ends the switch, with an `INFO` line, and clears the repositories whose requests the pinned provider failed since its last response (`failed`). The classification switches once the pinned provider has failed the requests of two repositories and a failure would use an attempt (`1_classify_repos.Classifier.again`), and the server of the tools on the first failure of a summary (`classification_tools.Summarizer`). The pinned provider is the endpoint whose responses the pilots checked and whose prices the cost estimate assumes, and a test goes without the retries of the SDK (`TEST_RETRIES`), so that it costs at most one request that the pinned provider fails, after which the same request goes to the backup provider. `retire` ends a switch and sends the backup provider no further request in the invocation, with a `WARNING`, as the classification does when a streak of responses that fail the response format ends with a response of the backup provider (`1_classify_repos.Classifier.format_failed`). A model without a backup provider never switches, and neither does a model with a retired one (`available`)
- Both services refuse a request for spent credit (`credit_refusal`), and a refused request costs nothing. OpenRouter refuses it with HTTP 402, "Your account or API key has insufficient credits. Add more credits and retry the request", or with HTTP 403 for a spent guardrail budget, workspace budget or key limit, which `error.metadata.limit_source` names ([errors](https://openrouter.ai/docs/api-reference/errors)), and OpenAI with `insufficient_quota` or `billing_hard_limit_reached`. A top-up ends such a refusal, and the classification waits for it (`CreditPause` in `classify-repos-spec.md`). The refusal names its service and what a person does: add credits at https://openrouter.ai/settings/credits or raise the credit limit of the OpenRouter API key, or raise the quota or the billing limit of the OpenAI project (`TOP_UP`)
- A 402 of OpenRouter with the `limit_source` `openrouter_in_flight_budget` is no spent credit, because the requests in flight fill the budget for requests in flight, and OpenRouter's advice is to "wait for the `Retry-After` header and retry" ([limits](https://openrouter.ai/docs/api-reference/limits)). The classification takes it as a failure of the service (`in_flight`)
- A rejected key (HTTP 401) and a key or a project without access (HTTP 403 without a budget) stay refused after a top-up, and `classification_tools.refusal` stops the run on them. An error of OpenRouter has the HTTP status as an integer `code` in its body, where an error of OpenAI has a string or none, and the refusal names OpenRouter's key for it (`from_openrouter`)
- OpenRouter also responds with HTTP 403 when it blocks content: "Forbidden (insufficient permissions, guardrail block, or moderation flag)" ([errors](https://openrouter.ai/docs/api-reference/errors)). An input that moderation flagged has `reasons` and `flagged_input` in `error.metadata`, and a guardrail's block, "Request blocked: prompt injection patterns detected", has `patterns` (`blocked`). Such a block concerns the request alone. OpenRouter blocks the same content again and lets other content through, so neither `credit_refusal` nor `classification_tools.refusal` reads it as a refusal
- `KeyCredit` reads the credit that an OpenRouter API key has left from `GET https://openrouter.ai/api/v1/key`, which spends nothing. The credit is the least of the key's `limit_remaining`, "Remaining credits for the key, or null if unlimited", and the `remaining_usd` of its `effective_budget`, "The budget that blocks requests first, or null" ([limits](https://openrouter.ai/docs/api-reference/limits)). For a key without a limit or a budget, the credit is unlimited, and the log states no amount, because the balance of the account takes a management key to read (`GET /api/v1/credits`)
- `unserved` reads OpenRouter's endpoint list of a model from `GET https://openrouter.ai/api/v1/models/{author}/{slug}/endpoints`, which spends nothing and responds without a key ([list all endpoints for a model](https://openrouter.ai/docs/api/api-reference/endpoints/list-endpoints)), and gives the reason that the pinned endpoint serves no request with the parameters of a model: the list has no such model (HTTP 404), no endpoint with the provider slug, the endpoint in another quantization, the endpoint without one of the parameters among its `supported_parameters`, or the endpoint with a `max_completion_tokens` below the output limit of the requests, because such an endpoint would end a response before the limit of its request. Every request of a model that labels sends `reasoning` and `tools`, the tool of the checklist among them (`CLASSIFYING_PARAMETERS`), and of its settings those that are set (`request_parameters`, `SETTING_PARAMETERS`): `temperature`, `top_p`, `seed` and the output limit, which the list names `max_tokens` and a request of the Responses API sends as `max_output_tokens`: "On Chat Completions (`/api/v1/chat/completions`), the same budget is `max_tokens`" ([reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)). The summary model's requests send `reasoning` (`SUMMARY_PARAMETERS`). The pinned endpoints of DeepSeek V4.1 Flash and GLM-5.3 list all of them, and OpenRouter's endpoint list of 2026-11-02 gives both a `max_completion_tokens` above the output limit. The requests set no `tool_choice`, which not every endpoint supports in each of its values (`supports_tool_choice`). With `require_parameters`, OpenRouter responds to each request to an endpoint without a parameter with HTTP 404 "No endpoints found". The reason names the endpoints in the same quantization that serve the parameters. On 2026-10-30 the list gave Chutes' mxfp4 endpoint of Kimi K3 without `tools`, and Z.ai's own fp8 endpoint of GLM-5.3 Flash without `structured_outputs`, which the requests needed then, because they set the response format as a `text` format
- `unsupported_effort` reads the entry of a model in OpenRouter's model list, `GET https://openrouter.ai/api/v1/models` (`model_list`), which spends nothing and responds without a key, and gives the reason that OpenRouter does not take the reasoning effort of the model's requests as it is: the list has no such model, or the model's `reasoning` lists `supported_efforts` without the effort or omits them. OpenRouter's [reasoning page](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens): "supported_efforts: Filter effort selectors to these values ... When null, all gateway effort values are accepted. When omitted, the model does not expose effort selection". Under its heading "Google Gemini 3 Models with Thinking Levels", the same page says "If a model doesn't support a specific effort level ..., OpenRouter will map your requested effort to the nearest supported level", and no page says which level another model gets. On 2026-11-02 the list gave DeepSeek V4.1 Flash the efforts `max`, `high`, `low` and `none`, and GLM-5.3 `max`, `high` and `low`, and neither the effort `medium` that the classification had sent
- The two pinned models carry the settings of their requests in their records (`Settings`, `Endpoint.settings`), which the maintainer set on 2026-11-02: DeepSeek V4.1 Flash at reasoning effort high (`REASONING_EFFORT`), temperature <!--s:parameters.2_classification.endpoints.TEMPERATURE-->0.6<!--/s--> (`TEMPERATURE`), top_p <!--s:parameters.2_classification.endpoints.TOP_P-->0.95<!--/s--> (`TOP_P`), seed <!--s:parameters.2_classification.endpoints.SEED-->7<!--/s--> (`SEED`) and an output limit of <!--s:parameters.2_classification.endpoints.MAX_OUTPUT_TOKENS-->65,536<!--/s--> tokens (`MAX_OUTPUT_TOKENS`), with the higher temperature <!--s:parameters.2_classification.endpoints.HIGHER_TEMPERATURE-->1.0<!--/s--> (`HIGHER_TEMPERATURE`) and an output limit of <!--s:parameters.2_classification.endpoints.HIGHER_MAX_OUTPUT_TOKENS-->262,144<!--/s--> tokens (`HIGHER_MAX_OUTPUT_TOKENS`) for its attempts at a repository after a failed response (`Settings.higher`), and GLM-5.3 at the same effort and seed with the output limit <!--s:parameters.2_classification.endpoints.HIGHER_MAX_OUTPUT_TOKENS-->262,144<!--/s--> and temperature <!--s:parameters.2_classification.endpoints.SECOND_MODEL_TEMPERATURE-->1.0<!--/s--> and top_p <!--s:parameters.2_classification.endpoints.SECOND_MODEL_TOP_P-->0.95<!--/s--> (`SECOND_MODEL_TEMPERATURE`, `SECOND_MODEL_TOP_P`). DeepSeek documents the top_p of its model and recommends an output limit in the recommended sampling parameters of its [model card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash), `| top_p | 0.95 or 1.0 |` and `| max_tokens | ≥ 256K |`, with K counted as 1024 as DeepSeek's [API reference](https://api-docs.deepseek.com/api/create-chat-completion) counts it ("384K (393216)"). The attempts at the higher temperature and GLM-5.3 send the least recommended value as <!--s:parameters.2_classification.endpoints.HIGHER_MAX_OUTPUT_TOKENS-->262,144<!--/s--> tokens (`HIGHER_MAX_OUTPUT_TOKENS`). Z.ai documents the temperature and the top_p of GLM-5.3, the `"temperature": 1.0` and `"top_p": 0.95` of its [`generation_config.json`](https://huggingface.co/zai-org/GLM-5.3/blob/main/generation_config.json). The effort high, the temperature <!--s:parameters.2_classification.endpoints.TEMPERATURE-->0.6<!--/s--> of DeepSeek V4.1 Flash, the seed and the output limit of <!--s:parameters.2_classification.endpoints.MAX_OUTPUT_TOKENS-->65,536<!--/s--> tokens at that temperature, which lies below DeepSeek's recommendation, are the maintainer's choices, and the runs of the variant `deepseek_deepseek-v4.1-flash-morph_fp8-medium-temperature-0.6-seed-7` in the check of 2026-11-02 (`prompt_check_2026-11-02.csv`) supported the temperature. The model card of DeepSeek V4.1 Flash recommends `| temperature | 1.0 |`, the example of DeepSeek's inference README runs with `--temperature 0.6`, and the model card of DeepSeek-R1 advises for that model "Set the temperature within the range of 0.5-0.7 (0.6 is recommended) to prevent endless repetitions or incoherent outputs". Both model cards report their evaluations at the effort max, and high is a level that both models take. The settings are part of each record rather than constants that apply to every model, and two records of one model at one place are equal whatever their settings. `settings_of` gives an endpoint the settings of its record, of the pinned record of the same model id and Hugging Face id on any endpoint, because the settings belong to the weights that they were chosen for, `medium` alone for an OpenAI model (`OPENAI_REASONING_EFFORT`), whose reasoning models reject a temperature, and for any other OpenRouter model the effort and the seed of the pinned models and the output limit of the second model, <!--s:parameters.2_classification.endpoints.HIGHER_MAX_OUTPUT_TOKENS-->262,144<!--/s--> tokens (`HIGHER_MAX_OUTPUT_TOKENS`), without a temperature or a top_p (`OTHER_MODEL`), so that its endpoint applies the defaults of its provider rather than the values chosen for another model. A setting that is None is not sent: "When a sampling parameter is absent from your request, OpenRouter omits it upstream rather than substituting a hardcoded value, so the provider applies its own default" ([parameters](https://openrouter.ai/docs/api-reference/parameters))

## Module: `endpoints.py`

### Function structure

**`Endpoint`**: a model with the provider slug, the quantization and the Hugging Face id of its endpoint, with `service`, `openrouter`, `parameters()`, `of(recorded)`, `routing()`, `described()` and `described_with(backup)`

**`BACKUPS`**, **`backup_of(found)`**, **`with_provider(found)`**, **`Providers`**, **`PINNED_CHECK_SECONDS`**, **`TEST_RETRIES`**: the backup provider of each pinned model and of an endpoint, the endpoint of a recorded block with its provider, which of the pinned provider and the backup provider serves the next request of a model (`next`, `serving`, `available`, `failed`, `switch`, `responded`, `retire`), and the retries of the SDK for a request that tests the pinned provider

**`endpoint(model, provider, quantization, hugging_face_id)`**, **`PRODUCTION`**, **`SECOND_MODEL`**: the endpoint of a model, or `ValueError` for an OpenRouter model without one of the three or an OpenAI model with one of them. `PRODUCTION` is DeepSeek V4.1 Flash on Morph's fp8 endpoint, which the maintainer chose on 2026-10-31 as the classifying model and the summary model, and `SECOND_MODEL` is GLM-5.3 on Morph's fp8 endpoint, the second model, which labels the evaluation sample of the label evaluation and, in a run of another model, the repositories that the classifying model leaves without a decision after the retry rounds and a failed response. When `endpoint` gets the model id of `PRODUCTION` or `SECOND_MODEL` with no provider, quantization or Hugging Face id, or with those of its record, it returns that record with its settings (`PINNED`)

**`Settings`**, **`settings_of(found)`**, **`request_parameters(settings)`**, **`OTHER_MODEL`**: the settings of the requests of a model that labels, with `sampled()`, `recorded()`, `largest_output_tokens()`, `parameters()`, `higher()` and `of(recorded)`, the settings of an endpoint, the names in `supported_parameters` of the parameters of its requests, and the settings of an OpenRouter model without a record

**`api_key(service, credentials_path, environ)`**, **`client(found, credentials_path, timeout, max_retries, environ)`**, **`NoKey`**: the first API key of a service and the SDK's client of a model's service, or the error that names the missing key

**`credit_refusal(error)`**, **`CreditRefusal`**, **`in_flight(error)`**, **`blocked(error)`**, **`from_openrouter(error)`**: the refusal for spent credit that an error states, with its service, its reason and what to do, the full budget of the requests in flight, the reason that OpenRouter blocked the content of a request, and whether an error came from OpenRouter

**`KeyCredit`**: the credit of an OpenRouter API key, from a GET that a caller can replace

**`unserved(found, parameters, get, max_output_tokens)`**, **`Delisted`**, **`CLASSIFYING_PARAMETERS`**, **`SETTING_PARAMETERS`**, **`SUMMARY_PARAMETERS`**, **`HTTPStatusError`**: the reason that the pinned endpoint serves no request with the parameters of a model or generates fewer tokens than the output limit, from a GET that a caller can replace, a `Delisted` reason for an endpoint that the list does not name, from which the classification starts a model on its backup provider (`1_classify_repos.endpoint_check`), the parameters of the requests of a model that labels and of the summary model, and the error of a GET with an error status

**`unsupported_effort(found, effort, listed)`**, **`model_list(get)`**: the reason that OpenRouter does not take a model's reasoning effort as it is, and OpenRouter's model list by model id, from a GET that a caller can replace

## Error handling & edge cases

| Scenario | Behavior |
|----------|-----------|
| An OpenRouter model without a provider slug, a quantization or a Hugging Face id, an unknown quantization, or an OpenAI model with one of them | `ValueError` with the reason, which the commands log as `ERROR` before any request |
| No API key of the model's service | `NoKey`, which names the environment variable and the credentials file |
| `GET /api/v1/key` fails, returns a status other than 200 or a body without an object at `data` | `OSError` or `ValueError`. The classification logs a `WARNING` and tests the credit with a request instead |
| The endpoint list fails, returns a status other than 200 or 404, or a body without a list at `data.endpoints` | `OSError` or `ValueError`. The classification logs a `WARNING` and tests the endpoint with the first request instead |
| The model list fails or returns a body without a list at `data` | `OSError` or `ValueError`. The classification logs a `WARNING` and sends the effort without the check |

## Tests

See `test_endpoints.py`, which uses the standard library's `unittest`. An error is built as the SDK builds it from a response with the body of OpenRouter's or OpenAI's error responses, and the credit of a key and the endpoint list of a model come from a fake GET.

- **`TestTheEndpoint`** (9): a model id with its author is an OpenRouter model; the second model named without an endpoint is called on its pinned endpoint; the production model named without an endpoint is called on its pinned endpoint; an OpenRouter model needs its provider, quantization and weights; an OpenAI model has no endpoint of OpenRouter; the routing pins one endpoint without fallbacks; the parameters name the model, its weights and its quantization and not the provider, a block recorded since names no provider and is called on the pinned provider, and a block recorded before keeps its provider; each pinned model has a backup provider of the same weights and quantization with its settings, and no other endpoint has one; the client of an OpenRouter model calls OpenRouter's API with its key
- **`TestTheProviders`** (6): the pinned provider serves until a switch; after a switch the backup provider serves and one request every `PINNED_CHECK_SECONDS` tests the pinned provider; a response of the pinned provider ends the switch; a retired backup provider ends the switch and takes no further switch; a model without a backup provider never switches; a switch and its end are logged
- **`TestTheRefusals`** (5): spent credit is a refusal for credit of its service; a full budget of requests in flight is waited out, not topped up; content that moderation or a guardrail blocks concerns that request alone; a rejected key or a key without access stays refused; other errors are neither a refusal for credit nor a refusal of every request
- **`TestTheCreditOfAKey`** (3): the credit left is the least of the key limit and the effective budget; a key without a limit or a budget is unlimited, and a spent limit leaves no credit; a response without the data of the key cannot be read
- **`TestTheEndpointList`** (7): an endpoint with every parameter of the requests serves them, and the request sends no key; an endpoint without a parameter serves none, and the reason names those that serve them; an endpoint without a temperature, a top_p, a seed or the output limit serves no request of the classifying model and serves the summary model's; an endpoint that generates fewer tokens than the output limit serves none; a missing endpoint or one in another quantization serves none; a model that OpenRouter does not list has no endpoint; a list that cannot be read raises
- **`TestTheModelList`** (3): an effort that the model list does not give the model is refused, as `medium` for both pinned models, and `high` is taken; an effort of a model without a list of efforts is taken when the list is null and refused when it is omitted, and a model that the list lacks is refused; a model list that cannot be read raises
- **`TestTheSettings`** (5): each pinned model has the settings that the maintainer set, with the higher temperature of DeepSeek V4.1 Flash; the attempts after a failed response take their own output limit, and the endpoint has to generate the larger one; a pinned model keeps its settings on any endpoint of its weights, and other weights under its model id, another OpenRouter model and an OpenAI model have settings that name no other model's temperature; a higher temperature needs a lower one to raise; the settings that a block of parameters records are read back

Run with:

```shell
python3 -m unittest test_endpoints -v
```

## Known limitations

- The credit of an OpenRouter API key without a limit or a budget cannot be read without a management key. A run then tests the credit of such a key with one request after each wait, which costs nothing when OpenRouter refuses it
- A model id names its weights only as far as OpenRouter keeps the id on the same weights. The Hugging Face id in the classification parameters records which weights the id stood for when the run started, and nothing checks that OpenRouter's model list still gives the same id
