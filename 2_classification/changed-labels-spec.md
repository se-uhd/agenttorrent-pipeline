# The labels that changed since the previous run

## Context

Each monthly run of the classification labels a new sampling frame. The classification reuses most labels from the cache of labels and labels a repository again when its README, its description, the model or the classification parameters changed. A later run can label a repository differently because the repository changed, because the classification changed, or because the model gave the same input another label, as its response varies from one request to the next. `changed_labels.py` finds the cause for every repository with an outcome that changed between a run and the previous run over a sampling frame. It is the last step of a run of `1_classify_repos.py` over the whole sampling frame. `compare_with_previous_runs` in `1_classify_repos.py` compares the latest finished run over a sampling frame. It also compares every earlier run with a comparison that an earlier invocation started and did not finish. It makes the comparisons oldest first and writes all of them, in that order, to `../data/classification/label_changes.csv` beside the run's other outputs. The `previous_run` column of each row gives the run that the row was compared with. If the function wrote only the latest run's comparison, it would overwrite the comparison of an earlier run that the same invocation finished first, and the changes of that earlier run would never be shown. Before the comparison of a run, the file lists the comparisons of the earlier runs over the same retrieval that lead to the run, oldest first (`earlier_comparisons` in `1_classify_repos.py`). They are found from the run backward: the run that it is compared with, then the run that this one was compared with, and so on, as long as each is over the retrieval and the scope of the run and has its comparison in the cache of labels. A finished run that left repositories without a decision and the new run that tries them again are over the same retrieval (`main` in `1_classify_repos.py`). The file therefore lists the changes of the finished run before those of the new run, also when a kill ended the new run and a later invocation compares it, and when a later invocation writes the comparison of the new run again from the cache of labels (`complete_finished_run`). If the file listed only the comparisons of one invocation, such an invocation would replace the changes of the retrieval with the changes of the new run.

`compare_with_previous_runs` leaves out an older run with a comparison that no invocation started. The comparison labels again with the classifier of the current code, which differs from the classifier of an older run once the code has changed. The function also returns at the first comparison that fails, and a failed comparison of an old run would keep every later run from being compared. Run on its own, `changed_labels.py` compares any finished run with any earlier run.

## Key decisions

- **Language:** Python 3.14, with the standard library, `label_cache.py`, `readmes.py`, `1_classify_repos.py` for its classifier, `costs.py` for the cost record of the run, and `agentcontext.logs` and `agentcontext.credentials`
- The previous run is the last finished run over a whole sampling frame before the compared run. The index of the cache of labels records the scope of each run. A run over a list of repositories (a label evaluation) or over the first N repositories (a trial) is never the previous run, because its labels come from another model or cover only part of the sampling frame
- The comparison reads the outcomes of a run from its labels file, `<id>.labels.csv.xz`, which records the outcome of every repository with the run that made its decision. The decisions file of a run contains only the decisions that the run made, and it does not record the outcome that the run gave a repository with a reused decision
- The comparison pairs repositories by GitHub id and compares a renamed repository under its new name
- The comparison labels a repository with a changed label again with the run's own classifier, that is, the model and the classification parameters that the run recorded. It rebuilds the parameters from the record, with the weights and the quantizations of the classifying model and the summary model that they name, the settings of the classifying model's requests and the reasoning effort of the summary model (`run_endpoints`), the tools of the bridge and the code, and it calls the model through OpenAI or OpenRouter (`connect`). The provider is no classification parameter since the maintainer's decision of 2026-11-04. A record from before that day names the provider of each model, and the repeats go to that provider. A later record names none, and the repeats go to the pinned provider of the same weights and quantization in `endpoints.py` (`called`, `endpoints.with_provider`), or, for a model without a pinned record, such as a candidate model of a check, to the provider that served most of the run's own responses of the model, apart from its backup provider, as the decisions name it under `served_by` and `summary_provider` (`served_providers`). Where a failure of the pinned provider would use an attempt, the repeat goes to the backup provider of the model, as in the labeling, unless `--no-backup-provider` is given or the check before the labeling found that the backup provider serves no request of its role (`1_classify_repos.backup_for`). The rebuilt parameters match the recorded digest by their keys, the digests without the provider (`label_cache.ParameterKeys`), and a change between two decisions under digests with one key changes neither the model nor the parameters (`changed_inputs`). The higher temperature and the second model are no classification parameters, and the label records them (`classify-repos-spec.md`). A label that the classifying model made at its higher temperature is repeated at the temperature, the top_p, the seed and the output limit of its record `higher_temperature`, and a label that the run's second model made is repeated by the second model at the endpoint and with the settings of its record `second_model`, for both READMEs of the repository (`Comparison.repeater`, `fallback_classifier`, `fallback_key`). A record of the higher temperature without an output limit was written while those attempts sent the limit of the run's other requests, and its repeat sends that limit. The repeats make no attempt at another temperature. The classifier that made a label is the second model of such a decision, the run's model at the temperature of a label of its higher temperature, and the run's model otherwise (`labeled_by`), and a change of it between the two labels counts as a changed model. A repeat measures one classifier, and a repeat that fails is not made by another. Parameters recorded before they named the classifying model cannot be sent again. The key of the rebuilt parameters can differ from the key of the recorded hash, such as after a new image changed a tool description or the summary prompt while the run's comparison was unfinished, and an OpenRouter model of the run can have neither a recorded provider, nor a pinned one, nor one that its decisions name. The comparison then repeats no label (`ParametersChanged`). The labels that an earlier invocation repeated are kept, and the cause of every other repository is undetermined, with the reason. The comparison logs the reason as a `WARNING` and writes its results. If it stopped instead, every invocation would fail, and the stages after the classification would never run
- When GitHub or the model fails a repeated request, the comparison tries the repository again after the others, in up to the classification's `RETRY_ROUNDS`, each after a wait of `RETRY_ROUND_SECONDS`, as the run does for a repository without a decision. A retry round keeps the results that the rounds before it paid for. `Comparison` keeps the current README's repeated label by GitHub id until the repository is compared. As soon as the label is made, `Comparison` writes it to the partial file as a line with the status `repeated`. The classifier also keeps a model's response for which GitHub then failed to return the facts of a mirror or a fork (`assess` of `1_classify_repos.py`). When GitHub fails for the facts of the previous README of a fork, the retry round therefore requests only those facts again. Labeling the current README again would cost another request, and a label that differs from the first would turn the cause into model variation. Before the facts are requested, `Comparison.keep_response` also writes the model's response for either README to the partial file as a line with the status `kept`, and the next invocation restores it (`kept_responses` of `1_classify_repos.py`). Without that line, the next invocation would pay the model for the previous README again after a stop, a kill or a failure of GitHub that outlasts the retry rounds between the response and the facts
- Once GitHub has failed the repeated requests of two repositories since its last response, every worker pauses, as in the labeling, and sends the request again after the pause (`GitHubPause`, `classify-repos-spec.md`). A repository that GitHub failed earlier, in this invocation or in an earlier one, has a `failed` line with the reason `github` in the partial file. When GitHub fails such a repository again, the comparison sends GitHub the README request that GitHub served last (`readmes.Client.responds`). While GitHub returns a usable response to that request, the repository fails on its own and begins no pause. Until GitHub has served the comparison a README request, the comparison uses the README of a compared decision as that request, from a repository that GitHub did not fail before (`failed_on_github`, `readmes.Client.served_earlier`). A retry round or a resumed comparison can hold only repositories for which GitHub fails every request, and this check keeps them from pausing every worker through every wait of `GITHUB_PAUSES`. When GitHub returns no usable response to that request either, the failure counts toward the pause as any other failure does, so that the comparison waits out an outage of GitHub that begins in a retry round. After the last pause, a failure of GitHub for a repository that did not wait for the pauses stops the comparison (`GitHubDown`), and the next invocation resumes it. Without this stop, an outage of GitHub would outlast the retry rounds and fail more repositories than the ceiling
- The API refuses a malformed request the same way every time (`ModelFailure.final` of `1_classify_repos.py`). The retry rounds of the invocation therefore do not repeat a label that the API refused as malformed, as the labeling does not label such a repository again, because each round would pay again for the earlier requests of the conversation. A repository with a repeated request that still fails after the retry rounds keeps an undetermined cause, with the error as the repeat's `unavailable`, as long as such repositories number no more than the classification's ceiling for as many repositories as the run's labels list (`undecided_ceiling`). A `WARNING` names the first of them, and the comparison is written with exit 0. The comparison runs after a full labeling, and if every failed repository stopped it, one repository for which GitHub returns HTTP 502 through a burst would stop every stage after the classification. More failed repositories than the ceiling point to an outage of GitHub or the model that outlasted the retry rounds, and a written comparison would leave each of their causes undetermined for good. The comparison then exits 1 and keeps its partial file, `compared_with` stays empty, and the next invocation repeats the labels that failed
- The comparison stops with exit 1 when the API refuses every request, when the API's service fails through every pause (`ServiceDown`), when GitHub fails through every pause (`GitHubDown`), or when GitHub refuses every GitHub access token through the checks of `readmes.RECHECK_WAITS`. The next invocation resumes it. When the comparison stops after it labeled the current README and before it labeled the previous README, the partial file keeps the `repeated` line. The next invocation takes the current README's label from that line (`read_repeated`) and sends only the previous README. A label kept only in memory would have to be paid for again, and a second label that differs would turn the cause into model variation. Every stop, also for an error that the classification does not expect or for a model that the API no longer offers, ends the pauses for spent credit, for the API's service and for GitHub as in the labeling, so that a waiting worker does not hold the comparison for the longest wait (`Comparison.end_pauses`). The comparison checks the GitHub access tokens as the labeling does. Before the first request, it drops a GitHub access token only when GitHub returns HTTP 401 for it, and it fills an empty pool again after the waits of `readmes.RECHECK_WAITS` (`readmes-spec.md`)
- The comparison sends the repeated requests on the service tier of the run that ends with the comparison, which `compare_with_previous_runs` passes on. When the module runs on its own, it uses the tier of `--openai-service-tier`, flex by default, as the labeling does. On the project's default tier, the repeated labels would cost twice what the labels cost. The tier sets the price and changes nothing that the model is given. The requests of an OpenRouter model name no tier, and the cost record prices each repeat at the provider that served it, the pinned provider or the backup provider
- The repeats are requests of the compared run. As each invocation of the comparison ends, it adds the tokens of its responses to the run's tokens file by the tier that each response reports (`label_cache.add_tokens`), as the labeling does. When the comparison stops or is written, it writes the run's cost record again and logs its total (`costs.record_or_warn`, `costs-spec.md`). If the record kept the cost that the run wrote as it ended, it would leave out the repeats, which the index adds to the run's tokens
- The comparison repeats labels with the models of the compared run, which the API can retire after the run. When the API no longer offers the classifying model or the summary model (`ModelNotOffered`), no invocation can repeat the remaining labels, and stopping would make every later invocation fail. The comparison then repeats no further label, as it does for classification parameters that the current code would not send. The labels that it repeated are kept, and the cause of every other repository is undetermined, with the reason. A `WARNING` gives the reason, and the comparison is written with exit 0
- In an invocation of the classification in which the second model labels nothing, as while its endpoint is unserved or its API key is missing, `1_classify_repos.py` passes the reason of its `WARNING` to the comparison (`second_model_unavailable` of `compare_with_previous_runs`). The comparison then repeats none of the labels that the second model made, because each of its requests would fail as the requests of the labeling would: a missing key would end the comparison with exit 1, and an unserved endpoint would pause and stop it. The comparison would then exit 1 in every invocation until the second model labels again. The labels of the second model that an earlier invocation repeated are kept, the cause of every other repository with a current label of the second model is undetermined, with the reason, and a `WARNING` gives the reason. The other labels are repeated as before. Run on its own, `changed_labels.py` gets no such reason and repeats every label
- In an invocation of the classification in which OpenRouter's lists show that the run's classifying model or summary model serves no request as it is, `1_classify_repos.py` passes the reason (`unserved` of `compare_with_previous_runs`). A comparison with a label to repeat then exits 1 with an `ERROR` that names the reason before its first request (`requests_unserved`), and a comparison without one writes its changes. The next invocation compares the run again. Run on its own, `changed_labels.py` gets no such reason
- A repository that the previous run left without a decision is compared with its outcome in the latest earlier run over a sampling frame that decided it (`decided_before`), and the change record has that run as its previous run. If the comparison used only the previous run, the change of a repository labeled `true`, then left without a decision, then labeled `false` would never be shown. A repository that no earlier run decided is counted as without a decision
- The repeated labels distinguish model variation from a changed input. The comparison labels the current README again at the run's revision, as the run labeled it (`assess` of `1_classify_repos.py`). It uses the description, the activity and GitHub's mirror flag that the decision recorded, the language check's result for the README, and the fork heuristic under the thresholds that the current decision recorded. It also takes the issues and pull requests, the metadata and the outline that the decision recorded for its first request, as calls of round 0 (`recorded_results` of `1_classify_repos.py`), and reads anew only a result that the decision lacks. Read anew, the metadata would hold GitHub's current description and the issues GitHub's current activity, and the cause would depend on data that neither decision was made on. A decision from the time when the model called these tools recorded no results of round 0, and the repeat of its input reads all three anew. The repeat reads anew a linked page that the model requests. Of the activity, the comparison shows only the fields that the current classifier shows (`shown_activity`), so that a previous decision made under the stars and the forks is not repeated with an input that the current classifier never gives. Applying the fork heuristic again keeps a fork that the run labeled `false` by the heuristic from being taken for a change of the model's response. A decision that records no thresholds is not repeated, and its cause stays undetermined. When the repeated label differs from the run's label, one input has two labels. The cause is then model variation, and the comparison sends no further request. Otherwise, when the README, the revision or the description changed, the comparison labels the previous README at the previous revision with the previous description. Each input then has two labels:

| Classifier | Previous input under the current classifier | Cause |
|---|---|---|
| unchanged | labeled as before | input change |
| unchanged | labeled otherwise than before | model variation |
| unchanged | the input did not change | model variation |
| changed | labeled as now | classifier change |
| changed | labeled as before | input change |
| changed | the input did not change | classifier change |
| changed | a third label | undetermined |
| either | its README cannot be read at its revision | undetermined |

- Two labels per input are the fewest that show variation, and no measurement of the model's stability exists to set a larger number. A cause other than model variation therefore means only that each input kept its label once. The model can still vary on that input
- A README is read at the decision's revision and checked against the decision's blob SHA. When a revision is gone, GitHub returns the README of the default branch. A README that does not match the blob SHA counts as unavailable, and the cause is undetermined
- The comparison reads a linked page when the model requests it and counts a page that changed between the runs as the same input
- The comparison determines without the model the cause of a changed outcome that involves an exclusion, because the README and the language check are deterministic. The cause is input change when the README changed, classifier change when only the classification parameters or the language check that the decision recorded changed, and undetermined otherwise
- When the classification carried a label over from an earlier decision without the model, the comparison determines its cause without the model too (`carried_cause`). The current decision contains the model's response from the previous decision, and a repeated request would only find that the same response gives the current label. A label counts as carried over from the previous decision when its `carried_from` contains that decision's `decided_at`, directly or among `earlier_decided_at`, the decisions that the source decision was itself carried over from. A run between the two that is not the previous run, such as a run over another sampling frame that a kill ended, can carry the label over first, and the compared run then carries it over from that run's decision. The cause is classifier change when the fork heuristic of another version decided the fork again, and undetermined when the thresholds changed as well. It is input change when GitHub's facts about a mirror or a fork changed, and classifier change otherwise, because only the rules and checks of the classification remain
- The comparison counts a repository that is gone in either run, new to the sampling frame or no longer in it, and does not compare it. It does the same for a repository that the compared run left without a decision (`undecided` in its labels file), which has no decision to compare, and for a repository that neither the previous run nor an earlier run decided
- The cache of labels keeps the repeated labels as `<id>.changes-NNN.jsonl.xz`, with everything that a decision records. When the comparison is written, their requests and tokens are added to the run's row of the index. The comparison writes each finished repository to a partial file and resumes from it. `start_comparison` begins the partial file as soon as both runs' labels are read, before any request to GitHub or the model, with the previous run in its first line. The next run over the sampling frame therefore finishes a comparison that failed before its first repeated label, such as a comparison without an OpenAI API key. Without this first line, a comparison that failed this early would never be made. A partial file of a comparison with another previous run is begun again, and its requests and tokens are added to the run's row, because resuming such a file would mix the repeated labels of two comparisons. Each line of the partial file records the requests and tokens spent since the line before it, and the requests and tokens of an invocation that a kill or an error ended therefore count too. Every reader of the partial file reads it one line at a time and leaves out a last line that a stop cut short, also when the cut falls inside a character of UTF-8 (`label_cache.partial_lines`)

## Module: `changed_labels.py`

### CLI interface

```
python3 changed_labels.py [--run RUN] [--previous RUN] [--cache-dir DIR] [--output-dir DIR]
                          [--workers N] [--openai-service-tier TIER] [--no-backup-provider]
                          [--credentials PATH]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--run` | the last finished run over a sampling frame | The run to compare |
| `--previous` | the run over a sampling frame that finished before it | The run to compare it with, which has to have started before the compared run |
| `--cache-dir` | `../data/classification/labels/` | The cache of labels |
| `--output-dir` | `../data/classification/` | The directory of `label_changes.csv` |
| `--workers` | <!--s:parameters.2_classification.1_classify_repos.WORKERS-->32<!--/s-->, as for the classification | Repositories compared at once |
| `--openai-service-tier` | `flex` | The OpenAI service tier of the requests that repeat the labels: `flex`, `default` for the standard tier, or `auto` for the project's setting |
| `--no-backup-provider` | off | Send every repeat to the pinned provider of its model, also while the pinned provider fails, instead of sending a repeat that would use an attempt to the backup provider of the model |
| `--credentials` | `credentials.csv` at the repository root | Read after the environment, by the comparison and by the MCP server of the tools, when a label is repeated |

### Function structure

**`outcome(row)`**, **`labeled_by(decision)`**, **`changed_inputs(previous, current)`**, **`pair(previous_rows, current_rows, decided_before)`**, **`decided_before(cache_dir, rows, previous_id)`**: a repository's outcome in a run's labels, the model that made a label, what differs between two decisions, the outcomes of two runs paired by GitHub id, and the latest earlier run that decided a repository that the previous run left without a decision

**`label_cause(previous_label, label, repeat, previous_input, classifier_changed)`**, **`outcome_cause(changed)`**, **`carried_cause(previous, current)`**: the causes, as the table and the decisions above give them

**`summary_of(decision)`**, **`change_record(...)`**, **`readme_as_labeled(github, name, repository_id, decision)`**, **`repeat(record, classifier, github, repeated, keep, keep_response, recorded_calls)`**: the fields of a decision that a change record keeps, the record of one changed repository, the README that a decision labeled, read again at its revision and checked against its blob SHA, and the repeated labels. `repeat` keeps the current README's repeated label in `repeated` for a retry round and passes it to `keep` as soon as it is made. `recorded_calls` holds the calls of round 0 that the current and the previous decision recorded, which `compare` reads off the decisions and `explain` and `Comparison` pass on

**`partial_lines(path, statuses)`**, **`read_partial(path)`**, **`read_repeated(path)`**: the lines of a comparison's partial file with the statuses that a reader needs, the comparisons that a stopped invocation finished, and the current README's repeated labels of the repositories that it did not compare

**`Comparison`**, **`explain(...)`**, **`connect(args, endpoint)`**, **`run_endpoints(recorded, run, served)`**, **`served_providers(decisions)`**, **`ParametersChanged`**, **`unrepeated(record, error)`**: the repeated labels of every changed repository. `Comparison` repeats them in retry rounds and again after each pause for GitHub that a repository waits for (`take`), and it writes the model's responses that wait for GitHub's facts to the partial file (`keep_response`). Its `unrepeatable` gives the reason when the API no longer offers a model of the run's classifier, and `repeater` gives the classifier that repeats a record. `explain` repeats the labels with the run's classifier on the run's service tier, with the backup provider of each model that `backups` gives, and a label of the higher temperature or of the run's second model with the settings that it records, `run_endpoints` reads the endpoints of the run's models from its recorded parameters, each with the provider on which the comparison calls it (`called`), `served_providers` gives by role the provider that served most of the responses of the run's decisions apart from the backup providers, and `connect` builds the clients of GitHub and of the classifying model's service from the credentials. `ParametersChanged` is raised for classification parameters that the current code would not send, and `unrepeated` returns a record with labels that could not be repeated

**`compared_in(partial)`**, **`start_comparison(cache_dir, rid, previous_id)`**, **`write_changes_csv(cache_dir, output_dir, run_ids)`**, **`added(rid, cache_dir, totals)`**: the previous run in the first line of a partial file, the begun partial file of a comparison, `label_changes.csv` from the cache, and the comparison's requests and tokens added to the run's row

**`compare(args, connect, bridge_for)`**, **`report(...)`**, **`main(argv)`**: the comparison and its summary

### Output

`../data/classification/label_changes.csv` has one row per repository with a changed outcome, in the order of the run's sampling frame, for each comparison that the invocation made or wrote again from the cache of labels, oldest first, each after the comparisons of the earlier runs over the same retrieval that lead to its run, as the context describes. The columns are `repo_name`, `cause`, `previous` and `now` (a label or `excluded: <reason>`), `changed` (any of `readme`, `revision`, `description`, `model`, `parameters` and `language_check`, where `model` means that another model made one of two labels (`labeled_by`) or that the classifying model, the Hugging Face id of its weights, its quantization or a setting of its requests differs between them, while a difference in the provider alone is no change, and `parameters` that the rest of the classification parameters (`label_cache.shared_parameters`) differ), `repeat_label`, `previous_input_label`, `previous_run`, `justification` and `previous_justification`. `../data/classification/labels/<id>.changes-NNN.jsonl.xz` contains the same repositories with the README, revision, model, parameters and justification of both decisions, and each repeated label as a decision records it. The comparison fills `compared_with`, `label_changes` and `changes_sha256` in the run's row of `../data/classification/labels/index.csv`, adds the tokens of the repeats to `<id>.tokens.csv` and writes `<id>.cost.csv` again. The summary in the log gives the number of repositories that kept their outcome, changed it, are new, left, have no decision in one of the two runs, are gone or are back, and the number of changes by cause.

## Error handling & edge cases

| Scenario | Behavior |
|----------|-----------|
| No earlier run over a sampling frame | An empty `../data/classification/label_changes.csv`, `INFO repository_labeling: ... no earlier run to compare it with.`, exit 0 |
| No finished run with its labels | `ERROR repository_labeling: The cache of labels ... has no finished run ...`, exit 1 |
| `--previous` is the run itself or a later run | `ERROR repository_labeling: Run ... did not start before run ...`, exit 1. A run compared with itself shows no change, and a run compared with a later run shows every change backwards |
| The current code would send other classification parameters than the run recorded | `WARNING repository_labeling: The classification parameters of the current code differ from the parameters that run ... recorded ...`, no request. The labels that an earlier invocation repeated are kept, every other cause is undetermined with the reason, and the comparison is written with exit 0 |
| A label must be repeated and a credential is missing | `ERROR repository_labeling: The comparison cannot be made, because ...`, exit 1 |
| The second model labels nothing in the invocation of the classification that ends with the comparison | `WARNING repository_labeling: The second model labels nothing in this invocation. ...`, no request to the second model. The labels of the second model that an earlier invocation repeated are kept, the cause of every other repository with a current label of the second model is undetermined with the reason, the other labels are repeated, and the comparison is written with exit 0 |
| GitHub fails a repository that it failed earlier, in this invocation or in an earlier one, and responds to the README request that it served last | The repository fails on its own, with a `WARNING`, and begins no pause |
| GitHub fails a repository that it failed earlier, and returns no usable response to the README request that it served last either | The failure counts toward the pause as the failure of any other repository |
| GitHub returns no usable response for the repeated requests of two repositories since its last response | `WARNING repository_labeling: GitHub returned no usable response for N repositories since its last response ...`. Every worker pauses for the next wait of the classification's `GITHUB_PAUSES` and then sends the request again |
| The model fails a repeated request after its attempts, or GitHub returns no response or a response that is not the JSON that it documents, and the repository does not wait for a pause for GitHub | `WARNING` for the repository. The other repositories are compared, and the repository is tried again in up to the classification's `RETRY_ROUNDS`, unless the API refused the request as malformed, which no retry round sends again. A repository that still fails keeps an undetermined cause, with the error, and a `WARNING` names the first. Exit 0 |
| More repositories fail through the retry rounds than the classification's ceiling for as many repositories as the run's labels list | `ERROR repository_labeling: N of M repositories have no repeated label after the retry rounds, more than the ceiling of C for R repositories ...`, exit 1 with the partial file kept and `compared_with` empty. The next invocation repeats the labels that failed |
| GitHub accepts no GitHub access token after the waits of `readmes.RECHECK_WAITS`, or fails a repository that did not wait for the pauses for GitHub after the last of them, or the API rejects the API key or denies the project or the key access, or a service refuses the requests for spent credit through the longest wait of the classification's pause for credit, or its service fails every request through the classification's pauses | Every worker stops, and the comparison exits 1 with the partial file kept. The next run over the sampling frame, or the next invocation, repeats only the repositories that are left |
| The API no longer offers the classifying model or the summary model of the compared run (`model_not_found`) | `WARNING repository_labeling: The API does not offer the model ...`, or `The API refuses the requests of the summary model (the API does not offer the model ...)`, no further request. The labels that the comparison repeated are kept, every other cause is undetermined with the reason, and the comparison is written with exit 0 |
| A repository that the compared run left without a decision | Counted, not compared |
| A repository that the previous run left without a decision | Compared with the latest earlier run that decided it, which the row gives as its previous run, or counted when no earlier run decided it |
| A comparison stopped or killed between the model's response for a README and GitHub's facts | The next invocation takes the response from the `kept` line of the partial file and reads only GitHub's facts |
| A comparison stopped or killed after it wrote `label_changes.csv` and before the index row recorded its previous run | The index does not record the comparison. The next invocation therefore compares the run again from the partial file, without a request, and writes the same CSV. `label_changes.csv` is written before the index row, because a comparison that the index records counts as complete. If the index row came first, the classification would begin a new run after the next Start, and the comparison of that run would replace the CSV |
| A README cannot be read at its revision | Cause undetermined, with GitHub's response |
| A cache file changed since it was written | `ERROR repository_labeling: The comparison cannot be made, because ...`, exit 1 |
| The labels of a run refer to a run that contains no decision for the repository | `ERROR repository_labeling: The comparison cannot be made, because ...`, exit 1 |

## Known limitations

- Each input is labeled twice. A cause other than model variation does not rule out that the model varies on the input with a smaller probability.
- A linked page is read live, and the comparison cannot distinguish a page that changed between the runs from an unchanged page.
- A repeat takes the results of round 0 in the format in which its decision recorded them. A previous decision made under other classification parameters can hold them in another format than the current classifier gives, as when a field of a result was added or removed since.
- The repeat of a decision from the time when the model called these tools reads the issues and pull requests, the metadata and the outline anew, and its input holds GitHub's data at the time of the comparison.
- A README at a revision that is gone, or a repository deleted after the run, leaves the cause undetermined.
